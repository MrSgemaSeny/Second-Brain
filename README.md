# 🧠 Brain's Protocol

### Личный «второй мозг» соло-разработчика. Живой контекст для AI-сессий, который знает твой стек, твои проекты и твою историю — и передаёт их каждому новому AI за секунды.

> Не Obsidian-свалка заметок. Это исполняемый протокол: AI читает контекст → пишет код → прогоняет тесты → фиксирует лог → только потом делает `git push`.

---

## Проблема, которую решает Brain's Protocol

Каждый соло-разработчик, работающий с AI-агентами (Claude, GPT-4o, Gemini, OpenHands, Claude Code), сталкивается с одним и тем же:

- Объясняешь каждому новому AI свой стек — **каждую сессию заново**.
- AI пишет код «в вакууме», не зная архитектурных решений прошлых сессий.
- После деплоя нет истории «что, зачем и почему изменилось» — только коммиты, в которых часто нет контекста.
- Повторяешься: одни и те же грабли (Flyway, IDOR, WebSocket на iOS Safari) находятся вручную в каждом новом проекте.

Brain's Protocol решает всё это одной структурой и тремя правилами.

---

## ⚡ Что это даёт

| До | После |
|---|---|
| 10 минут объяснять AI «я пишу на Spring Boot + React, использую FSD» | AI читает `context/me.md` и стартует с полного контекста |
| AI предлагает микросервисы «потому что модно» | AI знает принцип: модульный монолит + FSD на старте |
| Забыл, почему в JF-1C сделана роль ADVISOR | Открываешь `journal/2026-08-10/jf-1c.md` — там вся цепочка решений |
| Одинаковый баг повторяется в трёх проектах | Занесён в `knowledge/` — следующий AI его обходит |
| Коммит «fix» без контекста | Лог сессии перед пушем: что, зачем, какие тесты прошли |

## 🚀 Как это работает

### Три правила протокола

```
ПРАВИЛО №1 → Перед сессией AI читает context/*
ПРАВИЛО №2 → После зелёных тестов AI пишет в journal/ перед git push
ПРАВИЛО №3 → AI дополняет prompts_for_ai.md при новых паттернах
```

### Главное правило системы

```
ТЕСТЫ ПРОШЛИ → AI ПИШЕТ В BRAIN'S PROTOCOL → GIT PUSH
Никогда наоборот. Никогда без лога.
```

### Протокол сессии в действии

```
┌─ ДО НАЧАЛА ──────────────────────────────────────────────┐
│ 1. context/me.md        → кто я, стек, принципы            │
│ 2. context/projects.md  → активные проекты и статусы      │
│ 3. context/rules.md     → железные правила разработки     │
│ 4. context/prompts_for_ai.md → режимы, паттерны, опыт     │
│ 5. knowledge/           → релевантные архитектурные хаки   │
│ 6. projects/{active}/   → детали текущего проекта         │
│ 7. journal/последний    → что было сделано в прошлый раз   │
│ → AI подтверждает готовность и начинает работу            │
└───────────────────────────────────────────────────────────┘
         │
         ▼  (работа с полным контекстом — помнит историю)
┌─ ПОСЛЕ ЗЕЛЁНЫХ ТЕСТОВ ─────────────────────────────────────┐
│ 1. journal/YYYY-MM-DD/{project}.md по шаблону session-log   │
│ 2. Обновить projects/{project}/ при смене статуса           │
│ 3. Экстрагировать хаки/багфиксы в knowledge/                │
│ 4. Дополнить prompts_for_ai.md новыми паттернами           │
│ 5. git push                                                 │
└─────────────────────────────────────────────────────────────┘
```

Приоритет при конфликте решений: `Security > Correctness > Performance > Code Cleanliness`.

## 👤 Кому это нужно

**Соло-разработчикам и small-team фаундерам**, которые:

- Ведут 2–5 проектов параллельно и теряют контекст между ними.
- Работают с разными AI (Claude, GPT-4o, Gemini, OpenHands) — каждый раз заново объясняя одно и то же.
- Хотят историю решений, а не только коммиты.
- Устали повторять одни и те же архитектурные грабли.
- Принимают архитектурные решения сами и хотят, чтобы AI говорил как peer, а не как джун.

## 🔧 Техническое ядро (dev-to-dev)

### Стек, под который заточен протокол

**Backend:** Java 17, Spring Boot 3, Spring Security, JPA/Hibernate, PostgreSQL, Flyway, Caffeine Cache, Bucket4j, WebSocket (STOMP).
**Frontend:** React 19, TypeScript, Vite, Tailwind CSS v4, Feature-Sliced Design, React Query, Framer Motion.
**Infra:** Docker, GitHub Actions, Fly.io, GitHub Pages.
**Extra:** Python, FastAPI, MediaPipe.

### Архитектурные принципы (вшиты в контекст)

- Модульный монолит на бэкенде (не микросервисы на старте).
- FSD на фронтенде — всегда.
- Security first — безопасность в архитектуре, не патч.
- Migrations only — схема БД только через Flyway, никогда руками.
- Working over perfect — работающий MVP важнее идеальной архитектуры.

### Железные правила (AI нарушать не может)

```text
НИКОГДА  не менять применённые Flyway-миграции
НИКОГДА  не хардкодить секреты в коде
НИКОГДА  ddl-auto=update в продакшене
НИКОГДА  @PostConstruct для DB-операций — только ApplicationReadyEvent
ВСЕГДА   тесты перед пушем
ВСЕГДА   FSD на фронтенде
ВСЕГДА   security в архитектуре с первого дня
```

### Два режима общения с AI

- **Режим 1 (по умолчанию) — Senior Architect peer:** уточняющие вопросы, рассуждения вслух, трейд-оффы, прямой пуш-бэк на плохие решения.
- **Режим 2 — поддержка/эмпатия:** тёплый тон, честность не снижается, критика только по запросу или если критично для безопасности.
- Переключение фразами: «включи режим 2» / «вернись в обычный режим».

### Совместимость с AI-инструментами

| Инструмент | Интеграция |
|---|---|
| **Claude / Gemini** | Промпт «Senior Software Architect и наставник» в `prompts_for_ai.md` |
| **Claude Code** | Авточтение `CLAUDE.md` из корня репо (шаблон в `templates_for_projects/claude.md`) |
| **OpenHands** | Модель Claude Sonnet, формат задач `[Действие] [Что] [Где] [Acceptance]` |
| **GPT-4o** | Промпт под Full-Stack (Spring Boot + React TS), production-ready |

## 🚀 Быстрый старт

```bash
git clone https://github.com/MrSgemaSeny/Second-Brain.git
cd Second-Brain
```

1. Открой vault в Obsidian (или любом Markdown-редакторе).
2. Отредактируй `context/me.md` под свой стек и принципы.
3. Заполни `context/projects.md` своими проектами.
4. В начале каждой AI-сессии давай AI прочитать 4 файла из `context/`.
5. После зелёных тестов — пиши в `journal/YYYY-MM-DD/{project}.md`, затем push.

### Скормить контекст AI одним сообщением

```text
Прочитай Brain's Protocol перед началом работы:
1. context/me.md
2. context/projects.md
3. context/rules.md
4. context/prompts_for_ai.md

Ты знаешь мой стек, проекты и архитектурные принципы.
Приоритеты: Security > Correctness > Performance > Code Cleanliness.
После зелёных тестов — обнови journal/ перед push.
```

## 🛡️ Что этот репозиторий НЕ делает

- Не генерирует код сам — он даёт контекст тому, кто генерирует.
- Не заменяет git-коммиты — он дополняет их человеческим контекстом.
- Не CRM и не трекер задач — это контекстный слой над твоей реальной работой.
- Не пытается угодить менеджерам — это инструмент программиста для программиста.

## 🧭 Философия в одном абзаце

Мне важна детерминированность — база данных меняется только через миграции, а не «накатили руками». Мне важна ролевая безопасность на уровне архитектуры, а не патчей поверх дыр. И мне важно доводить проект до реального использования живыми людьми, а не оставлять его демкой в портфолио. Brain's Protocol — это та же дисциплина, перенесённая на работу с AI: контекст зафиксирован, история неизменяема, решения осознанны.
