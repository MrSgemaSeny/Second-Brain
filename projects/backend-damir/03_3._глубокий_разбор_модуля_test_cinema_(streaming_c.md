## 3. Глубокий разбор модуля test_cinema (Streaming Core)

Основная инженерная задача этого модуля — обеспечить плавное воспроизведение тяжелых видеофайлов (например, `Boycovskiy_club.mp4`) в браузере клиента без необходимости полного скачивания файла на устройство.

### 3.1 Механика HTTP Range Requests (Видеостриминг)
Если отправить 2-гигабайтный видеофайл обычным HTTP `GET` запросом (возвращая `FileResponse`), браузер попытается скачать его целиком. Это убьет оперативную память сервера (OOM) и заставит пользователя ждать.

**Архитектурное решение в FastAPI:**
Реализован кастомный обработчик, который парсит HTTP-заголовок `Range`.
1. Клиент (HTML5 `<video>`) запрашивает фрагмент: `Range: bytes=0-1048575` (первый мегабайт).
2. FastAPI читает заголовок и открывает файл `Boycovskiy_club.mp4` в режиме бинарного чтения (`rb`).
3. Сервер перемещает курсор (`file.seek(start_byte)`).
4. Читает только запрошенный чанк (размер чанка жестко лимитирован, например, 1-2 МБ, чтобы не перегружать сеть).
5. Сервер отвечает со статусом **HTTP 206 Partial Content**.
6. В ответе передаются критически важные заголовки:
   - `Content-Range: bytes 0-1048575/2147483648`
   - `Accept-Ranges: bytes`
   - `Content-Length: 1048576`
   - `Content-Type: video/mp4`

Благодаря этой реализации, пользователь может свободно кликать по таймлайну видео (перемотка), и сервер мгновенно отдаст нужный кусок файла с середины.

### 3.2 Управление метаданными фильмов
- API для CRUD операций над каталогом фильмов (Название, Описание, Режиссер, Год выпуска, Жанры, URL к видеофайлу).
- Использование Pydantic-моделей для строгой валидации входящих JSON-пейлоадов при добавлении новых фильмов.
