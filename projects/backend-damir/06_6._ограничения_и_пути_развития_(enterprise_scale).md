## 6. Ограничения и пути развития (Enterprise Scale)

1. **Стриминг:** Текущая реализация (раздача MP4 через HTTP Range) хороша для прототипа. В реальном Production Enterprise (Netflix) MP4 не раздают напрямую. Видео нарезается на тысячу маленьких файлов `.ts` (Transport Stream) по 2-10 секунд, и используется протокол HLS (HTTP Live Streaming) или DASH с файлом манифеста `.m3u8`. Это позволяет динамически менять качество видео (1080p -> 480p) при падении скорости интернета у клиента. Переход на HLS — следующий логичный шаг.
2. **Масштабирование Insight:** Когда матрица пользователей достигнет миллионов записей, вычисление косинусного сходства на лету (Real-time) станет невозможным. Потребуется переход на Batch-процессинг (например, запуск Apache Spark заданий раз в сутки), которые предвычисляют рекомендации и кладут их в Redis для быстрого доступа.
3. **Хранение видео:** Локальная директория с файлами не масштабируется при запуске в Kubernetes. Требуется интеграция с S3-совместимым хранилищем (MinIO, AWS S3) и стриминг через пре-подписанные URL.
