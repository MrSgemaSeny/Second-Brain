## 3. Архитектура обработки сообщений (STOMP Pipeline)

### 3.1 Конфигурация брокера (`WebSocketConfig`)
Проект содержит класс, аннотированный `@EnableWebSocketMessageBroker`.
- **Endpoint Registry:** `registry.addEndpoint("/ws").setAllowedOriginPatterns("*").withSockJS();` — точка входа для фронтенда.
- **Message Broker Registry:**
  - `enableSimpleBroker("/topic", "/queue");` — включение In-Memory брокера. `/topic` используется для публичных чатов (Broadcast), `/queue` — для приватных (один-на-один).
  - `setApplicationDestinationPrefixes("/app");` — префикс для сообщений, отправляемых от клиента на сервер.

### 3.2 Жизненный цикл сообщения
1. **Отправка:** Клиент шлет JSON в `/app/chat.sendMessage`.
2. **Контроллер:** Метод контроллера с аннотацией `@MessageMapping("/chat.sendMessage")` перехватывает сообщение.
3. **Бизнес-логика:** Внутри метода сообщение обогащается временной меткой (Timestamp), сохраняется в БД (PostgreSQL) через `chatMessageRepository.save()`.
4. **Рассылка:** Контроллер возвращает объект, и Spring автоматически отправляет его в топик (через `@SendTo("/topic/public")`), либо используется `SimpMessagingTemplate` для таргетированной отправки (`convertAndSendToUser`).

### 3.3 Приватные сообщения (Private Routing)
Реализация приватных сообщений — сложная задача. В Spring она решается через `SimpMessagingTemplate`.
- Клиент подписывается на `/user/queue/messages`.
- Сервер вызывает `messagingTemplate.convertAndSendToUser(recipientId, "/queue/messages", message)`.
- Под капотом Spring резолвит `recipientId` в конкретную сессию WebSocket и отправляет сообщение.
