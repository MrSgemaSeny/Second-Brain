## 1. Введение и концепция

### 1.1 Что такое Air Canvas
Air Canvas — это интерактивное веб-приложение нового поколения (Natural User Interface), позволяющее пользователю рисовать на экране компьютера, просто перемещая палец в воздухе перед веб-камерой. Приложение захватывает видеопоток, анализирует положение кисти руки в пространстве, распознает жесты и транслирует их в команды рисования на HTML5 Canvas.

Концепция проекта родилась из желания создать "виральный vibe-coded" продукт, который наглядно демонстрирует мощь современных браузерных технологий в связке с легковесным машинным обучением.

### 1.2 Ключевые возможности
- **Real-time трекинг руки:** Точное отслеживание 21 ключевой точки (landmarks) кисти руки с частотой до 30 кадров в секунду.
- **Распознавание жестов на лету:** Система эвристически определяет три базовых состояния (Рисование, Пауза/Ховер, Очистка экрана).
- **Плавный рендеринг:** Интерполяция кривых и настройка `lineCap='round'` для создания идеальных сглаженных линий, даже если камера пропускает кадры.
- **Зеркальный UX:** Интуитивно понятное управление, где лево на видео — это лево на экране (алгоритмическая компенсация перевернутого кадра).

## 2. Технологический стек

Проект разделен на два изолированных микросервиса, общающихся через WebSockets.

### 2.1 Бэкенд (ML & Networking)
- **Язык:** Python 3.10+ — стандарт де-факто для машинного обучения.
- **Фреймворк:** FastAPI. Используется исключительно для инициализации WebSocket-сервера и (при необходимости) раздачи статических файлов. FastAPI базируется на ASGI (Starlette), что делает его идеальным для асинхронного I/O.
- **Сервер:** Uvicorn — молниеносный ASGI-сервер на базе uvloop.
- **Computer Vision:** Google MediaPipe (модуль `solutions.hands`). Выбор обусловлен тем, что модель работает на CPU с минимальными задержками и не требует наличия VRAM, что критично для ноутбука с RTX 3050 (4GB), который лучше поберечь для других задач. OpenCV (`cv2`) используется для конвертации массивов и базовой обработки изображений.

### 2.2 Фронтенд (UI & Capture)
- **Ядро:** React 19, TypeScript, Vite.
- **Стилизация:** Tailwind CSS v4. Отказ от конфигурационных файлов в пользу плагина Vite.
- **Медиа API:** `navigator.mediaDevices.getUserMedia` для доступа к камере. HTML5 Canvas API (2D Context) для рендеринга.

## 3. Архитектура и потоки данных

Архитектура системы построена вокруг непрерывного, двунаправленного потока данных (Pipeline). Любая задержка на любом из этапов приведет к ощутимому лагу, поэтому архитектура спроектирована с учетом максимального сжатия и отбрасывания устаревших пакетов.

### 3.1 Жизненный цикл одного кадра
1. **Захват:** Скрытый тег `<video autoplay>` в React получает сырой поток с веб-камеры.
2. **Сэмплирование:** `requestAnimationFrame` в React перехватывает текущий кадр видео и отрисовывает его на скрытом оффшорном (off-screen) canvas размером строго 320x240 пикселей.
3. **Сжатие:** Вызов `canvas.toDataURL('image/jpeg', 0.7)`. JPEG используется вместо PNG, так как он весит в 4-5 раз меньше, а артефакты сжатия не мешают нейросети MediaPipe распознать руку.
4. **Транспорт (Up):** Отправка Base64 строки через WebSocket соединение.
5. **Декодирование:** Python получает строку, отрезает префикс `data:image/jpeg;base64,`, декодирует Base64 в байты, а затем через `cv2.imdecode` превращает в NumPy массив `(240, 320, 3)`.
6. **Inference:** Передача массива в `hands.process(image)`. Модель возвращает нормализованные координаты (от 0 до 1) всех 21 landmarks.
7. **Бизнес-логика:** Python вычисляет жест (эвристика углов и дистанций).
8. **Транспорт (Down):** Сервер сериализует JSON `{x, y, gesture}` и отправляет клиенту.
9. **Рендеринг:** React получает координаты, де-нормализует их (умножает на ширину/высоту реального холста), применяет сглаживание и вызывает `ctx.stroke()`.

## 4. Подсистема компьютерного зрения (Python/MediaPipe)

### 4.1 Топология руки (Landmarks)
MediaPipe выдает 21 точку для каждой руки. Для проекта критичны следующие:
- `0`: Wrist (Запястье, базовая точка отсчета)
- `4`: Thumb_tip (Кончик большого пальца)
- `8`: Index_finger_tip (Кончик указательного пальца) — **Главная точка для рисования**
- `12`: Middle_finger_tip (Кончик среднего пальца)
- `16`: Ring_finger_tip (Кончик безымянного)
- `20`: Pinky_tip (Кончик мизинца)

### 4.2 Эвристика распознавания жестов
Распознавание жестов базируется не на тяжелых нейросетях классификации, а на быстрой математической эвристике (расчет евклидова расстояния и вектора направления).

- **Жест "Рисование" (Draw):**
  Условие: Поднят ТОЛЬКО указательный палец. 
  Математика: `y` координаты точки 8 (index tip) значительно выше (меньше в пикселях, так как ось Y идет вниз), чем `y` точки 6 (index PIP). При этом пальцы 12, 16, 20 согнуты — их `y` координаты ниже их соответствующих PIP суставов.

- **Жест "Пауза/Ховер" (Hover - Peace Sign):**
  Условие: Подняты указательный и средний пальцы (точки 8 и 12), остальные сжаты.
  Действие: Перемещение виртуального курсора без оставления следа на холсте.

- **Жест "Очистка" (Clear - Кулак):**
  Условие: Все кончики пальцев (8, 12, 16, 20) находятся в непосредственной близости к основанию ладони (расстояние до точки 0 минимально).
  Действие: Полная очистка холста.

## 5. Подсистема WebSocket (FastAPI)

### 5.1 Управление соединениями
FastAPI использует `fastapi.websockets.WebSocket`. 
Архитектура поддерживает механизм ConnectionManager для отслеживания активных клиентов. Хотя проект не подразумевает мультиплеер, грамотное управление пулом предотвращает утечки памяти при перезагрузке страницы (zombie connections).

### 5.2 Защита от перегрузки (Backpressure)
Так как фронтенд шлет кадры без остановки, сервер может захлебнуться (очередь обработки будет расти, порождая лаг в несколько секунд).
Решение: **Drop Policy**. 
Сервер не имеет очереди. Он обрабатывает только последний пришедший кадр. Если во время инференса приходит новый кадр, он просто отбрасывается.

## 6. Структура фронтенда (React/Canvas)

Фронтенд спроектирован с учетом разделения ответственности: слой захвата медиа не должен знать о слое рендеринга.

### 6.1 Хук `useWebcam`
Анкапсулирует логику доступа к медиаустройствам. Возвращает `videoRef`, который монтируется в DOM с `display: none` (или как полупрозрачный фон `opacity-20`).

### 6.2 Хук `useWebSocket`
Управляет сетевым соединением. Обязательно включает логику Exponential Backoff для автоматического переподключения в случае падения Python-сервера.

### 6.3 Компонент `CanvasBoard`
Отвечает за HTML5 Canvas.
Содержит внутреннее состояние (не React State, а `useRef` для избежания лишних рендеров):
- `lastX`, `lastY`: Предыдущие координаты кисти.
- `ctxRef`: Ссылка на `CanvasRenderingContext2D`.

## 7. Алгоритмы и математика

### 7.1 Зеркалирование координат
Когда пользователь двигает руку вправо перед камерой, на видео рука двигается влево. Чтобы интерфейс был интуитивным, координаты X необходимо инвертировать (отзеркалить).
Формула:
```javascript
const realX = (1.0 - data.x) * canvasWidth;
const realY = data.y * canvasHeight;
```

### 7.2 Сглаживание линий
Если соединять точки прямыми линиями (`lineTo`), рисунок получится угловатым.
Оптимизация:
1. Использование квадратичных кривых Безье (`quadraticCurveTo`), где средняя точка между предыдущей и текущей координатой выступает как контрольная точка.
2. Конфигурация контекста: `ctx.lineCap = 'round'`, `ctx.lineJoin = 'round'`, `ctx.lineWidth = 8`.

## 8. Ограничения и Edge Cases

- **"Дрожание" (Jitter):** Модель MediaPipe имеет микроскопическую погрешность в определении координат на каждом кадре, из-за чего линия может дрожать даже если рука неподвижна.
  *Решение:* Применение алгоритма скользящего среднего (Simple Moving Average) на фронтенде для сглаживания последних 3-5 координат перед отрисовкой.
- **Выход руки из кадра:** Сервер присылает сообщение `{"status": "no_hands"}`. Клиент обязан немедленно сбросить переменные `lastX` и `lastY` в `null`, иначе при возвращении руки в кадр нарисуется прямая линия через весь экран.
- **Освещение:** Модель MediaPipe плохо справляется с жестким контровым светом (окно за спиной). Это архитектурное ограничение самой ML модели.

## 9. Сборка и развертывание

### 9.1 Локальная разработка
1. **Python (Backend):**
   ```bash
   cd backend
   python -m venv venv
   source venv/bin/activate # или venv\Scripts\activate
   pip install fastapi uvicorn mediapipe opencv-python websockets
   uvicorn main:app --reload --port 8000
   ```
2. **React (Frontend):**
   ```bash
   cd frontend
   npm install
   npm run dev
   ```

### 9.2 Будущий деплой
Для продакшена потребуется SSL (HTTPS). WebSockets должны работать по протоколу WSS, а `getUserMedia` в браузере работает только в безопасном контексте (HTTPS или localhost). Деплой Python бэкенда на Fly.io, а фронтенда на Vercel или GitHub Pages.
