## 3. Архитектура компонентов и State Management

Создание чат-клиента — одна из самых сложных задач фронтенда, так как требует синхронизации локального состояния с асинхронным потоком данных.

### 3.1 Архитектура Состояния (React State)
- **Messages State:** `const [messages, setMessages] = useState([])`. 
  - Проблема: При получении 10 сообщений в секунду, вызов `setMessages` 10 раз вызовет фризы рендеринга.
  - Решение: React 18 автоматически батчит обновления.
- **Connection State:** `const [isConnected, setIsConnected] = useState(false)`. Управляет отображением спиннера загрузки и блокировкой инпута при обрыве связи.

### 3.2 Жизненный цикл WebSocket соединения
Подключение к сокету — это сайд-эффект. Он инициализируется в `useEffect`.

```javascript
useEffect(() => {
  const socket = new SockJS('http://localhost:8080/ws');
  const stompClient = Stomp.over(socket);

  stompClient.connect({ Authorization: `Bearer ${token}` }, (frame) => {
    setIsConnected(true);
    
    // Подписка на публичный канал
    stompClient.subscribe('/topic/public', (payload) => {
      const message = JSON.parse(payload.body);
      setMessages(prev => [...prev, message]);
    });
  }, (error) => {
    // Обработка потери соединения (Reconnection logic)
  });

  return () => {
    if (stompClient) stompClient.disconnect();
  };
}, []);
```
Паттерн "Cleanup function" в `useEffect` критически важен. Если его не написать, при навигации между страницами (React Router) браузер будет плодить "зомби"-подключения (Memory Leak).
