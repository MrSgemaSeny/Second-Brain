## 4. Глубокий разбор бизнес-механик

### 4.1 Gacha-система (Открытие паков)
Система паков — ядро монетизации и удержания игроков (Retention). 

**Алгоритм открытия пака:**
1. **Валидация:** Проверка баланса юзера (`SELECT balance FROM users WHERE id = ?`).
2. **Транзакция:** Начало транзакции (`connection.setAutoCommit(false)`). Списание средств (`UPDATE users SET balance = balance - 100 WHERE id = ?`).
3. **Генерация RNG:** Кастомный алгоритм взвешенного рандома (Weighted Random).
   - *Legendary:* 1%
   - *Epic:* 9%
   - *Rare:* 30%
   - *Common:* 60%
4. Сначала выбирается редкость на основе `Math.random()`.
5. Затем выполняется запрос для выбора случайной карточки нужной редкости: `SELECT * FROM cards WHERE rarity = ? ORDER BY RANDOM() LIMIT 1`.
6. **Выдача лута:** Запись в инвентарь: `INSERT INTO inventory (user_id, card_id) VALUES (?, ?)`.
7. **Коммит:** `connection.commit()`.

### 4.2 Сборка состава (Squad Builder)
Пользователь может выставить 11 карточек в основной состав.
- **Химия (Chemistry):** Очки химии начисляются, если рядом стоящие игроки имеют одну национальность или играют в одном клубе. Это требует представления состава в виде графа, где узлы — позиции (ST, LW, RW), а ребра — линки между ними.
- **Рейтинг (Team OVR):** Среднеарифметическое всех карточек + бонус от химии. Высчитывается "на лету" при вызове команды `/squad`.

### 4.3 Боевая система (PvP Пенальти)
Механика асинхронного PvP, реализованная через Callback Queries (Inline-кнопки Telegram).

**Стейт-машина матча:**
1. Player 1 отправляет запрос Player 2 (`/challenge @username`). Состояние: `PVP_INVITE_SENT`.
2. Player 2 принимает вызов. Состояние обоих меняется на `PVP_IN_PROGRESS`.
3. Отрисовываются Inline-кнопки (Влево, По центру, Вправо).
4. Player 1 выбирает угол удара (данные сохраняются в кэше матча, но не показываются Player 2).
5. Player 2 выбирает угол прыжка вратаря.
6. Сервер сравнивает выбор. Если углы совпали — сейв вратаря. Если нет — гол. Зависимость вероятности гола корректируется разницей Team OVR двух игроков.
7. Смена ролей. Серия длится до 5 ударов или до "золотого гола".

### 4.4 Экономика и Торговля (Trade)
Сложнейший модуль, требующий ACID транзакций.
Пользователи могут меняться карточками (`testproject1_19`).
- **Сценарий:** 
  1. Юзер A предлагает Юзеру B обмен `Card 1` на `Card 2`.
  2. В БД создается запись `trades` со статусом `PENDING`.
  3. Обе карточки временно лочатся (запрет на продажу/удаление/кнопку квик-селла).
  4. Юзер B нажимает "Подтвердить".
  5. Запускается JDBC транзакция:
     ```sql
     BEGIN;
     UPDATE inventory SET user_id = {User B} WHERE id = {Card 1 ID} AND user_id = {User A};
     UPDATE inventory SET user_id = {User A} WHERE id = {Card 2 ID} AND user_id = {User B};
     COMMIT;
     ```
  6. Если кто-то попытался обмануть систему (передал карточку другому до коммита), транзакция откатывается по правилам изоляции БД.
