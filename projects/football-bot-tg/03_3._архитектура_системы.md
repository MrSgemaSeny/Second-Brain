## 3. Архитектура системы

Проект построен на паттерне **Command** и кастомной реализации конечного автомата (Finite State Machine).

### 3.1 Обработка входящих обновлений (Update Routing)
Каждое входящее сообщение (`Update`) проходит через единый диспетчер (Dispatcher), который:
1. Извлекает `chatId` и `userId`.
2. Проверяет текущее состояние пользователя (User State) в In-Memory кэше (`ConcurrentHashMap<Long, UserState>`).
3. Если состояние `IDLE`, сообщение парсится как команда (например, `/start`, `/packs`).
4. Если состояние активно (например, `WAITING_FOR_TRADE_CONFIRMATION`), сообщение передается в соответствующий обработчик состояния.

### 3.2 Архитектура базы данных (Схема)

Схема базы данных спроектирована с учетом реляционных связей:

**Таблица `users` (Профили):**
- `id` (BIGINT, PK) — Telegram User ID.
- `username` (VARCHAR) — Никнейм.
- `balance` (BIGINT) — Внутриигровая валюта (Coins).
- `gems` (INT) — Премиум-валюта.
- `experience` (INT) — Опыт для повышения уровня.
- `clan_id` (INT, FK) — Ссылка на клан.

**Таблица `cards` (Справочник футболистов):**
- `id` (INT, PK, AUTO_INCREMENT) — Уникальный ID карточки.
- `player_name` (VARCHAR) — Имя футболиста (например, "Lionel Messi").
- `overall_rating` (INT) — Базовый рейтинг (OVR).
- `position` (VARCHAR) — Позиция (ST, CAM, CB, GK).
- `rarity` (VARCHAR) — Редкость (COMMON, RARE, EPIC, LEGENDARY).
- `club` (VARCHAR) — Клуб.
- `nation` (VARCHAR) — Национальность.

**Таблица `inventory` (Коллекция юзера):**
- `id` (BIGINT, PK) — Уникальный ID экземпляра карточки.
- `user_id` (BIGINT, FK) — Владелец.
- `card_id` (INT, FK) — Ссылка на справочник.
- `is_in_squad` (BOOLEAN) — Экипирована ли карточка в основной состав.

**Таблица `clans` (Социальная механика):**
- `id` (INT, PK, AUTO_INCREMENT)
- `name` (VARCHAR) — Название клана.
- `owner_id` (BIGINT, FK) — Лидер клана.
- `trophies` (INT) — Очки рейтинга клана.
