## 4. Микросервисный ландшафт и DDD 

Система разбита на Bounded Contexts (Ограниченные контексты) в соответствии с Domain-Driven Design (DDD). Каждый сервис имеет свою собственную БД (или логическую схему), и прямой доступ к БД другого сервиса строго запрещен.

### 4.1 Identity Service
- **Функция:** Аутентификация (OAuth2/OIDC), управление пользователями, тенантами и ролями.
- **Технологии:** Keycloak (как IAM) + Spring Boot (для бизнес-логики управления тенантами).

### 4.2 Inventory Service
- **Функция:** Ядро запасов. Сверхвысокая нагрузка (тысячи транзакций в секунду при массовой инвентаризации).
- **Технологии:** Java 21, Spring WebFlux (Reactive), R2DBC, PostgreSQL.

### 4.3 Topology Service
- **Функция:** Управление физической структурой. Дерево ячеек. Расчет кратчайших путей для комплектовщиков.
- **Технологии:** Графовая база данных (Neo4j) для оптимизации поиска путей между стеллажами.

### 4.4 Gateway & BFF (Backend-For-Frontend)
- **Функция:** Единая точка входа для SPA и мобильных приложений.
- **Технологии:** Spring Cloud Gateway. Агрегация запросов (GraphQL).
