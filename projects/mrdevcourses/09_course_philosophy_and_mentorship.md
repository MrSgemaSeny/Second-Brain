# 9. Философия курса и Архитектура Менторства (MrDevCourses)

## 1. Психология и мотивы аудитории (16–25 лет)

### 1.1 Покупка трансформации идентичности
Человек покупает не абстрактные синтаксические конструкции HTML/CSS/Java, а **новую версию себя** («я тот, кто может создать и задеплоить свой собственный веб-сервис»).
- **Курс продает точку назначения**: «Первое веб-приложение онлайн».
- **Ключевой момент**: момент социального признания («смотри, я сам это сделал и выложил в интернет»).

### 1.2 Три драйвера аудитории
1. **Страх остаться за бортом (FOMO & Стыд)**:
   - Молодые люди видят бум AI, вайбкодинга и стартапов, но боятся показаться некомпетентными.
   - **Задача онбординга**: немедленно снять стыд в Уроке 0 («Ты не отстал, просто никто понятно не объяснял»).
2. **Желание сделать конкретный продукт**:
   - Автономия от дорогих разработчиков при реализации своей бизнес-идеи.
   - Не перегружать сухой теорией — давать видимый результат на каждом уроке.
3. **Проверка пригодности («Моё ли это»)**:
   - Минимальный порог входа в первые 2 часа. Быстрый дофаминовый win на Уроке 1 (деплой за 45 минут) исключает ранний отвал.

---

## 2. Разделение зон: Автоматизация vs Живой ментор

Главный принцип масштабирования: **автоматизируй рутину, оставь человеку эмоции**.

| Автоматизировано в LMS (Платформа) | Живой контакт ментора (Discord / 1-on-1) |
|---|---|
| Drip-разблокировка уроков по расписанию и дате | Первый онбординг-созвон (снятие психологического барьера) |
| Приём ссылки на GitHub & Live Demo | Поддержка при потере мотивации и выгорании |
| Первичный AI-грейдинг кода и AST-скан безопасности | Разбор концептуальных архитектурных развилок |
| FAQ и поиск по конспектам через Гибридный RAG | Разбор тупиковых ситуаций, когда студент не может сформулировать вопрос |
| Stuck Detection (алерты о неактивности $\ge 3$ дней) | Принятие решения о готовности студента к коммерческим заказам |
| Выдача верифицируемого PDF-сертификата | — |

## 3. Метанавык: «Как учиться с ИИ»

Студенты с нулевым опытом не обладают развитым навыком автономного обучения.
Попытка сделать систему полностью автономной без обучения этому навыку приводит к высокому отвалу (drop-off).

### Интеграция в программу:
1. **Урок 0**: Инструкция по работе с AI-ассистентом.
2. **Паттерн Error-Loop**: Обучение чтению консоли браузера и корректному формулированию баг-репорта для LLM.
3. **UX-правило платформы**: *«Сначала спроси ИИ-тьютора, затем пиши ментору»*.

## 4. Сквозной проект и структура программы

```
[Урок 0: Онбординг]       -> Снятие стыда + установка окружения + настройка ИИ-ассистента
[Урок 1: Первый Win]      -> Деплой готового шаблона на GitHub Pages / Vercel за 45 мин
[Урок 2: Вайбкодинг]      -> Модификация UI, стилей и логики через промпты
[Урок 3: Дебаг-мышление]  -> Чтение ошибок консоли, методы исключения, AST-безопасность
[Урок 4: Стейт и Данные]  -> Подключение БД / хранилища (Supabase / LocalStorage / REST API)
[Урок 5: Публикация]      -> Полировка README, скриншоты, добавление на Стену выпускников
[Урок 6: Что дальше?]     -> Карта развития: переход в Junior Dev или продуктовый вайбкодинг
```

---

## 5. Системные требования к LMS для поддержки философии

1. **Homework Verification Flow**:
   - Приём ссылок `repositoryUrl` + `liveDemoUrl`.
   - Автоматическая разблокировка урока при оценке AI $\ge 80$ или ручной аппрув ментора.
2. **Stuck Detection Engine**:
   - Анализ неактивности по `last_activity_at`.
   - При простое $> 72$ часов: автоматический Telegram-алерт ментору и поддерживающий Nudge студенту.
3. **Showcase & Proof-of-Work**:
   - Публичная витрина проектов выпускников как главное социальное доказательство для новых студентов.
