## 🎯 Философия Продукта и Менторства (Mr Developer Mindset)

1. **Все инструменты и настройки — прямо через сайт (Zero Friction Setup)**:
   - Студент не должен блуждать по Discord или внешним сайтам в поисках ссылок.
   - Каждый урок — это операционная карточка: прямые ссылки на установку (VS Code, Git, Antigravity, Cursor), готовые конфигурации, системные промпты, шаблоны и пошаговые чеклисты.
2. **Кнопка «Не получается / Сложно справляться» (Data-First RAG Dataset Collection)**:
   - На каждом шаге урока и в каждом задании размещается кнопка запроса помощи.
   - **Каждое нажатие обязательно сохраняется в PostgreSQL (`student_help_requests`)** со всеми параметрами: `student_id`, `lesson_id`, `step_index`, `problem_text`, `error_logs`.
   - Это формирует **золотой живой датасет** реальных затыков студентов и их формулировок, а не выдуманный синтетический FAQ.
   - Ментору в Telegram мгновенно падает push-уведомление с деталями проблемы.
3. **Telegram Dashboard Ментора (Управление на ходу)**:
   - Уведомления в Telegram:
     - Студент сдал ДЗ (имя + ссылки на GitHub и Live Demo)
     - Студент нажал «Не получается» (SOS-тикет)
     - Студент не заходил 3+ дней (Stuck detection)
     - Новая регистрация на платформе
   - Slash-команды в Telegram боте:
     - `/status` — сводка кто на каком уроке и прогресс потока
     - `/hw` — очередь непроверенных домашних заданий
     - `/approve <id>` — принять ДЗ прямо из Telegram
     - `/reject <id> <комментарий>` — вернуть на доработку с фидбеком
     - `/stuck` — список застрявших студентов (3+ дня без активности)
4. **Будущий AI с реальной RAG-системой (Vector Search по PostgreSQL pgvector)**:
   - Обучается и строит семантический поиск по накопленной базе реальных вопросов студентов и ответов ментора из `student_help_requests`.
   - Первая линия поддержки: снимает ~60% бытовых вопросов (ошибки консоли, синтаксис, типовые проблемы установки).
   - Если RAG не дал точного ответа — эскалация напрямую ментору.
5. **GitHub-Grade UX (Плотность, Читаемость, Честность)**:
   - Минималистичный интерфейс уровня GitHub (`#0d1117`, строгие бейджи, моноширинный код, zero-clutter).
   - Главный фокус — реальное знание студента и его первый работающий веб-проект, задеплоенный онлайн.

## 📅 Фазы Реализации

### Фаза 0 — Операционная основа (1-2 недели)
> **Цель:** 2 текущих студента работают полностью через сайт, Discord только для голосовых созвонов.

- [ ] **Урок как операционная карточка**: Прямые ссылки на софт, шаблоны, промпты, чеклисты.
- [ ] **Кнопка «Не получается»**: Модалка выбора шага + текст проблемы → Telegram Webhook ментору.
- [ ] **Telegram Бот & Уведомления**: Интеграция Telegram Bot API для отправки алертов о ДЗ и SOS-сигналах, базовые команды `/hw`, `/status`, `/approve`, `/reject`.
- [ ] **Dashboard студента (Focus Screen)**: Текущий урок, статус сданного ДЗ, countdown до открытия следующего дня.

### Фаза 1 — Закрытие пилота (3-4 недели)
> **Цель:** 2 первых студента дошли до финала и задеплоили свои веб-приложения на GitHub Pages / Vercel.

- [ ] **Stuck Detection**: Автоматический фоновый анализ (если 3 дня нет прогресса → пуш ментору и ободряющее сообщение студенту).
- [ ] **Публичная стена проектов (`/projects`)**: Галерея проектов выпускников с ссылками на живые сайты и репозитории.
- [ ] **Онбординг-флоу**: Приветственное руководство, цель курса и Discord-линк.

### Фаза 2 — Масштабирование: первый поток (10-20 студентов)
> **Цель:** Ментор тратит <2 часов в день за счёт RAG и автоматизации.

- [ ] **RAG-тьютор (pgvector) как 1-я линия**: Авто-ответы на типовые ошибки установки и синтаксиса перед вызовом ментора.
- [ ] **Асинхронный Q&A**: Прямой чат с ментором на платформе.
- [ ] **Реферальная система & Групповой прогресс**.

### Фаза 3 — Самодостаточный продукт (Long-Term)
> **Цель:** Студент проходит 80% пути автономно, ментор подключается на ключевые контрольные точки.

- [ ] Расширенная воронка аналитики отвала студентов по урокам.
- [ ] Монетизация и второй продвинутый курс.
