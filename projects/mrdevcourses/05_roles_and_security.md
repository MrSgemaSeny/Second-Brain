# 5. Ролевая модель и безопасность MrDevCourses

### 5.1 Роли и Матрица Доступа
- `STUDENT`: Просмотр каталога, запись на курс, доступ к урокам согласно drip-графику, сдача ДЗ и квизов, диалог с AI-тьютором, скачивание сертификатов.
- `ADMIN`: Полный доступ ко всем модулям, CRUD курсов/модулей/уроков/квизов/материалов, просмотр и переключение ролей студентов (`STUDENT <-> ADMIN`), ручной энролл, дашборд когорт и аудит-лог.

### 5.2 Защитные механизмы (Defense-in-Depth)

1. **IDOR & Row-Level Security (RLS)**:
   - Идентификация текущего пользователя строго через `SecurityUtils.getCurrentUserId()` из JWT клеймов.
   - Запрещено доверять `userId` из path variables или тела запроса для операций студента.

2. **Server-Side Drip Enforcement**:
   - Фронтенд только визуализирует статус (открыт/замок).
   - Сервер при запросе к уроку проверяет доступность по SQL-формуле `(NOW() - enrolled_at) >= ((day_number - 1) * INTERVAL '1 day')`. При попытке взлома возвращается `403 Forbidden` с таймштампом `opensAt`.

3. **Cookie & Session Security**:
   - `httpOnly = true`: Полная изоляция токена от JavaScript DOM и защита от кражи при XSS.
   - `SameSite = Lax`: Защита от межсайтовой подделки запросов (CSRF).
   - `Secure = true`: Передача токена только по HTTPS в production окружении.

4. **Tiered Rate Limiting (Bucket4j + Caffeine)**:
   - **Auth Tier**: 10 запросов / 15 минут на IP (защита от brute-force).
   - **AI Tier**: 5 запросов / минуту на пользователя (защита от исчерпания токенов Groq LLM).
   - **General Tier**: 60 запросов / минуту на пользователя/IP.
   - Заголовки ответа: `X-RateLimit-Remaining`, `Retry-After`.

5. **Quiz Anti-Cheat Protection**:
   - Поле `isCorrect` полностью вырезано из публичного API отдачи квиза.
   - Проверка ответов производится строго на сервере в транзакции.

6. **Static Code Security Scanner (Grader)**:
   - Проверка отправляемого студентом Java-кода на опасные конструкции AST (`Runtime.exec`, `ProcessBuilder`, `System.exit`, `Unsafe`, бесконечные циклы).

7. **Неизменяемый системный аудит (Audit Logs)**:
   - Фиксация всех административных действий (смена роли, зачисление, удаление урока) с сохранением ID актора, IP, UTC-времени и JSON-diff изменений.
