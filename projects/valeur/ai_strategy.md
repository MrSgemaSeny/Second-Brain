# Вектор развития AI (Phase 9) — Опыт HH.ru & MeDev

## Концепция AI Job Matcher
На основе анализа работы алгоритмов hh.ru и опыта нашего внутреннего проекта MeDev, для платформы Valeur выработан следующий вектор интеграции ИИ (в рамках `ai-service`).

### 1. Гибридная фильтрация (SQL + ИИ)
**Проблема**: Использование LLM для анализа 100% входящих откликов слишком дорого и медленно.
**Решение**: Воронка кандидатов должна иметь детерминированный отсев ("Автофильтры") до вызова ИИ. 
- Жесткие критерии (ЗП, минимальный опыт, город) фильтруются на уровне `application-service` (SQL/JPA). 
- ИИ (LLM) анализирует только тех, кто прошел этот базовый барьер, предотвращая сжигание токенов на заведомо нерелевантных кандидатов.

### 2. Семантический скоринг (вместо тупого Keyword Matching)
**Проблема**: Старые системы (как у hh.ru) отсеивают кандидатов, если те используют синонимы ("работа с клиентами" вместо "B2B-продажи").
**Решение**: Мы используем Llama 3 (через Groq). В отличие от TF-IDF, LLM понимает семантику. Однако промпт должен быть составлен так, чтобы ИИ:
- Распознавал синонимы для soft-skills и общих должностей.
- Требовал точного вхождения (Exact Match) для хард-скиллов (например, Spring Boot, React), если они помечены работодателем как критичные.

### 3. Геймификация "Completeness Score" (Заполненность профиля)
**Проблема**: Алгоритмы понижают пустые анкеты, но пользователи не всегда понимают почему.
**Решение**: Ввести `completeness_score` (от 0 до 100%) в `identity-service`. 
Итоговый процент мэтча кандидата с вакансией должен умножаться на этот скор. Это принуждает кандидатов максимально полно заполнять профиль (теги, навыки, опыт), повышая качество данных в платформе.

### 4. Авто-Нормализация должностей
**Проблема**: Креативные названия ("Ниндзя кода", "Специалист по счастью") ломают поиск и сбивают HR с толку.
**Решение**: Использовать опыт *MeDev Smart Sync*. При сохранении резюме или профиля, `ai-service` под капотом нормализует должность кандидата в стандартный рыночный термин (например, "Senior Backend Developer"). Кандидат видит своё креативное название, а алгоритмы ищут по `normalized_title`.
