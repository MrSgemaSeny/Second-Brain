## 4. Модули бэкенда

### 4.1 Модуль Auth (Аутентификация и авторизация)

Модуль auth — фундамент всей системы, обеспечивающий идентификацию и аутентификацию пользователей. Он включает управление пользователями, генерацию и валидацию JWT-токенов, OAuth2 авторизацию через Google, двухфакторную аутентификацию (TOTP), rate limiting для защиты от брутфорса и регистрацию новых пользователей с модерацией.

Сущность User хранит информацию о пользователе: email, password (bcrypt-хеш), имя, фамилию, роль, статус регистрации (PENDING, APPROVED, REJECTED), флаги 2FA и метаданные. RefreshToken связывает пользователя с токеном обновления, его сроком жизни и device-информацией для security-аналитики. TwoFactorPreAuth хранит промежуточные токены при логине с включённой 2FA до успешной верификации.

Контроллеры модуля: AuthController обрабатывает логин, логаут, регистрацию, refresh-токены и Google OAuth; TwoFactorController управляет настройкой, верификацией и отключением 2FA; UserController предоставляет CRUD для профиля пользователя.

Сервисы модуля: AuthService инкапсулирует логику аутентификации; JwtService генерирует и валидирует токены; RefreshTokenService управляет жизненным циклом refresh-токенов; TwoFactorService реализует TOTP-функциональность; GoogleAuthService обрабатывает OAuth2 flow; UserService управляет пользователями.

### 4.2 Модуль CRM (Управление отношениями с клиентами)

CRM-модуль — ядро платформы, обеспечивающее управление задачами, клиентами, воронкой продаж и Kanban-доской. Это наиболее объёмный модуль системы, включающий множество связанных сущностей и сложную бизнес-логику.

Сущности модуля:
- **Task** — задача с заголовком, описанием, статусом, приоритетом, дедлайном, исполнителем и клиентом
- **Stage** — стадия воронки с типом (OPEN, CLOSED, LOST) и порядком отображения
- **Pipeline** — воронка продаж, содержащая набор стадий
- **Client** (ClientProfile) — профиль клиента с контактной информацией
- **Subtask** — подзадача, привязанная к родительской Task
- **TaskComment** — комментарий к задаче
- **TaskActivity** — история изменений задачи (журнал аудита на уровне задачи)
- **UserLabel** — пользовательская метка для категоризации задач
- **CalendarEvent** — событие календаря с датой и участниками
- **LeadSource** — источник лида (referral, website, cold call)

Сервисы модуля: TaskService управляет CRUD задач, подзадач, комментариями, назначением исполнителей; ClientService обрабатывает профили клиентов; PipelineService управляет воронками и стадиями; DashboardService предоставляет данные для дашбордов (статистика по задачам, загрузке сотрудников); CrmAccessService реализует проверку прав доступа на уровне записей (row-level security); PipelineSeederService инициализирует стартовые пайплайны при первом запуске.

### 4.3 Модуль Billing (Биллинг и финансы)

Модуль billing автоматизирует финансовые операции: выставление счетов, управление подписками, отслеживание оплат и генерацию финансовых документов.

Сущности модуля: Invoice представляет счёт на оплату с номером, датой, суммой, списком услуг, статусом (DRAFT, SENT, PAID, OVERDUE, CANCELLED) и ссылкой на клиента; Subscription описывает рекуррентную подписку с периодом (monthly, quarterly, yearly), ценой и датой следующего платежа.

Сервисы модуля: InvoiceService управляет жизненным циклом счетов; SubscriptionService обрабатывает подписки и автоматическое продление; PdfGeneratorService генерирует PDF-версии счетов; InvoiceOverdueScheduler проверяет просроченные счета и обновляет их статус; InvoiceAccessService обеспечивает row-level доступ к финансовым данным.

### 4.4 Модуль Documents (Документооборот)

Модуль documents обеспечивает хранение, генерацию и управление документами. Платформа поддерживает два хранилища: DatabaseStorageService сохраняет файлы в базе данных (метаданные + blob), а LocalStorageService — в файловой системе приложения как fallback.

Сущности модуля: DocumentTemplate хранит шаблоны документов с типом (PDF, DOCX), содержимым (Thymeleaf-шаблон или poi-tl шаблон) и переменными для подстановки; Document представляет сгенерированный или загруженный документ со ссылкой на шаблон, параметрами генерации и статусом; StoredFile хранит бинарные данные файлов с MIME-типом, именем и размером.

Сервисы модуля: DocumentService управляет документами; DocumentGeneratorService генерирует документы из шаблонов; DocumentTemplateService управляет шаблонами; StorageService определяет интерфейс хранилища; DocumentAccessService проверяет права доступа к документам; DocumentDataLoader загружает данные из БД для подстановки в шаблоны; OfficialDocumentTemplateSeeder инициализирует стандартные шаблоны.

Контроллеры модуля: DocumentController предоставляет CRUD для документов; DocumentTemplateController управляет шаблонами; FileDownloadController обеспечивает безопасное скачивание файлов с проверкой доступа.

### 4.5 Модуль Courses (LMS — Система управления обучением)

Модуль courses реализует полноценную систему управления обучением с поддержкой курсов, глав, уроков, прогресса и сертификации.

Сущности модуля: Course описывает курс с названием, описанием, изображением, статусом (DRAFT, PUBLISHED, ARCHIVED); Chapter представляет главу внутри курса с порядковым номером; Lesson определяет урок с типом контента (VIDEO, TEXT, QUIZ), содержимым и длительностью; LessonProgress отслеживает прогресс пользователя по урокам; Enrollment связывает пользователя с курсом; Certificate хранит выданные сертификаты; CourseCurator назначает кураторов курсов.

Сервисы модуля: CourseService управляет курсами; LessonService обрабатывает уроки; LessonProgressService отслеживает прогресс; CourseAccessService проверяет доступ к курсам.

Контроллеры модуля: AdminCourseController для CRUD курсов администратором; LearnerCourseController для студентов; CuratorCourseController для кураторов; AdminMediaController для загрузки медиа.

### 4.6 Модуль Chat (Коммуникации)

Модуль chat обеспечивает коммуникацию между пользователями через WebSocket с протоколом STOMP. Поддерживаются личные сообщения и групповые диалоги.

Сущности модуля: ChatMessage хранит сообщение с отправителем, получателем, содержимым, временной меткой и статусом прочтения.

Сервисы модуля: ChatService обрабатывает отправку и получение сообщений.

Конфигурация модуля: WebSocketConfig настраивает STOMP-эндпоинт, SockJS fallback и авторизацию подписок.

### 4.7 Модуль Notifications (Уведомления)

Модуль notifications управляет отправкой уведомлений через email и Telegram, а также внутренними уведомлениями в приложении.

Сущности модуля: Notification представляет внутреннее уведомление с типом, содержимым, статусом прочтения и получателем.

Сервисы модуля: NotificationService управляет уведомлениями; EmailNotificationService отправляет email через SMTP; TelegramNotifierService отправляет алерты в Telegram; DeadlineAlertScheduler проверяет дедлайны задач и отправляет напоминания.

### 4.8 Модуль Audit (Аудит)

Модуль audit обеспечивает журналирование всех действий пользователей в системе. HibernateAuditListener автоматически перехватывает операции INSERT, UPDATE, DELETE и записывает их в таблицу audit_log.

Особенности аудита: маскирование чувствительных полей (SENSITIVE_FIELDS выводятся как [PROTECTED]); защита таблиц аудита от изменения через PostgreSQL триггеры; связь с пользователем через user_id.

### 4.9 Модуль Search (Глобальный поиск)

Модуль search предоставляет единый интерфейс для поиска по различным сущностям системы: задачам, клиентам, документам, курсам.

Сервисы модуля: GlobalSearchService выполняет поиск по всем типам сущностей с пагинацией.

Контроллеры модуля: GlobalSearchController предоставляет эндпоинт `/api/v1/search`.

### 4.10 Модуль Landing (Публичные страницы)

Модуль landing обрабатывает заявки с публичных страниц сайта: ContactRequest для обращений через форму обратной связи, ContactRequestFile для прикреплённых файлов.

Сервисы модуля: ContactRequestService обрабатывает заявки и уведомляет администраторов.

### 4.11 Модуль Services (Каталог услуг)

Модуль services управляет каталогом услуг, которые компания предлагает клиентам. Услуги могут быть привязаны к подпискам или выставляться разово.
