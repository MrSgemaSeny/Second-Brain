## 5. Структура фронтенда

### 5.1 Слои FSD

**Shared Layer** содержит код, переиспользуемый во всех частях приложения. В shared/api/ находится http.ts — централизованная обёртка над fetch для всех API-запросов. Она автоматически добавляет заголовки авторизации, обрабатывает refresh-токены, парсит JSON-ответы и транслирует ошибки. Shared/ui/ содержит базовые компоненты: кнопки, инпуты, модалки, карточки. Shared/lib/ включает утилиты: форматирование дат, валидация, хелперы. Shared/i18n/ настраивает react-i18next и хранит переводы.

**Entities Layer** определяет типы данных и операции для бизнес-сущностей. Каждая сущность имеет директорию с файлами:
- model.ts — TypeScript-интерфейс или тип
- api.ts — функции для API-запросов (используют apiRequest из shared)
- hooks/ — хуки для управления данными через React Query (useTask, useClient, useUser)

Сущности фронтенда включают: user (аутентификация, профиль), task (задачи, подзадачи), client (клиенты), pipeline (воронки), course (курсы), document (документы), invoice (счета), chat (сообщения), notification (уведомления), audit (журнал аудита), calendar (события).

**Features Layer** инкапсулирует пользовательские сценарии, объединяя несколько сущностей и UI. Примеры фичей:
- features/auth — логин, логаут, регистрация, восстановление пароля
- features/task — создание задачи, редактирование, комментарии
- features/2fa — настройка двухфакторной аутентификации
- features/contact-form — форма обратной связи
- features/leads — управление лидами
- features/task — операции с задачами
- features/notifications — управление уведомлениями
- features/labels — метки задач
- features/service-modal — модалка услуги

**Widgets Layer** содержит крупные, относительно независимые блоки UI, которые могут использоваться несколькими страницами. Примеры виджетов:
- widgets/task-board — Kanban-доска с драг-дропом
- widgets/chat/ — чат-виджет с WebSocket
- widgets/header/ — шапка приложения с навигацией
- widgets/footer/ — подвал
- widgets/dashboard/ — виджеты дашборда
- widgets/search/ — глобальный поиск
- widgets/task-create/ — форма создания задачи
- widgets/task-reject/ — диалог отклонения задачи
- widgets/pricing-table/ — таблица цен
- widgets/reviews/ — отзывы
- widgets/hero/, widgets/trust/, widgets/team/, widgets/offices/ — секции лендинга

**Pages Layer** представляет собой страницы приложения, соответствующие маршрутам роутера. Каждая страница компонует виджеты и фичи для реализации пользовательского сценария. Страницы включают:
- pages/auth/ — LoginPage, RegisterPage
- pages/dashboard/ — DashboardPage
- pages/admin/ — AdminEmployeesPage, AdminClientsPage, AdminPipelinesPage, AdminDashboardPage
- pages/admin-security/ — AdminSecurityPage для настройки 2FA
- pages/profile/ — ProfilePage
- pages/task-details/ — TaskDetailsPage
- pages/services/ — ServicesPage
- pages/about/ — AboutPage
- pages/home/ — HomePage
- Публичные страницы: Home, Services, About, Solution Picker, Contact, Leads

### 5.2 Управление состоянием

React Query управляет серверным состоянием — данными, которые приходят с API. Каждый хук использует структурированные query keys для организации кэша: ['tasks', 'list', filter] для списка задач, ['tasks', 'detail', id] для конкретной задачи. Это обеспечивает точную инвалидацию — изменение задачи инвалидирует только её кэш, не трогая остальные.

Локальное состояние (UI state) управляется через React hooks: useState для простых состояний, useReducer для сложных, useContext для состояния, доступного дереву компонентов (AuthContext для информации о пользователе).

### 5.3 Роутинг

Маршрутизация построена на react-router-dom с защитой маршрутов через компоненты-обёртки. Приватные маршруты (Dashboard, Admin) требуют аутентификации и проверяют роль пользователя. Публичные маршруты (Landing pages) доступны без авторизации.

### 5.4 Обработка ошибок

Централизованная обработка ошибок реализована на нескольких уровнях. HTTP-слой (shared/api/http) перехватывает HTTP-ошибки (401, 403, 404, 500) и транслирует их в typed exceptions. React Query настраивает retry-логику: 3 попытки с экспоненциальной задержкой для сетевых ошибок, немедленный fail для 4xx ошибок. UI-слой отображает ошибки через Toast-уведомления или inline-сообщения в зависимости от контекста.

### 5.5 WebSocket интеграция

STOMP-клиент подключается при инициализации приложения и использует JWT для аутентификации. Подписки на топики устанавливаются в компонентах, которым нужен real-time функционал (ChatWidget, NotificationsBell). При размонтировании компонента подписки отменяются для предотвращения утечек памяти.
