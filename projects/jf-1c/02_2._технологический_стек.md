## 2. Технологический стек

### 2.1 Бэкенд

Серверная часть платформы построена на современном Java-стеке с акцентом на стабильность и производительность. Ядро системы работает на Java 17 — версии с долгосрочной поддержкой, обеспечивающей баланс между новыми языковыми возможностями и совместимостью с библиотеками. Spring Boot 4.1.0 (pre-release/snapshot на момент 2026) и Spring Framework предоставляют инфраструктуру для построения RESTful API, управления транзакциями и внедрения зависимостей. ORM-слой реализован через Hibernate в связке с Spring Data JPA, что упрощает работу с базой данных через репозитории.

Для управления схемой базы данных используется Flyway версии 10+ с модулями flyway-core и flyway-database-postgresql. Миграции представляют собой SQL-скрипты с версионированием, что позволяет безопасно вносить изменения в структуру БД и откатывать их при необходимости. Текущая цепочка миграций включает версии от V1 до V110 и выше.

Сборка проекта осуществляется через Gradle — гибкий инструмент, поддерживающий как Java, так и другие JVM-языки. Для кэширования данных на уровне приложения используется Caffeine с per-region кэшированием, что обеспечивает низкую латентность для часто запрашиваемых данных без нагрузки на базу данных.

### 2.2 Безопасность аутентификации

Аутентификация реализована на основе JWT-токенов с полной поддержкой ротации и аннулирования сессий. Access-токен имеет короткий срок жизни и передаётся в заголовке Authorization, а refresh-токен хранится в httpOnly cookie для защиты от XSS-атак. Дополнительный уровень безопасности обеспечивается двухфакторной аутентификацией (2FA) на основе TOTP с генерацией QR-кодов и поддержкой резервных кодов восстановления.

Rate limiting реализован через Bucket4j и применяется на уровне фильтров Spring Security. Фильтры ApiRateLimitFilter и AuthRateLimitFilter ограничивают частоту запросов с одного IP-адреса, предотвращая брутфорс-атаки и злоупотребление API.

### 2.3 База данных

В качестве СУБД используется PostgreSQL 17.6 — мощная реляционная база данных с поддержкой сложных запросов, триггеров и процедур. На production-среде работает managed PostgreSQL от Fly.io, а для локальной разработки предусмотрен запуск через Docker Compose.

В PostgreSQL настроены триггеры, запрещающие выполнение UPDATE и DELETE операций на таблицах аудита, что гарантирует целостность журналирования действий пользователей. Это критически важно для соответствия требованиям финансового регулирования и внутреннего контроля.

### 2.4 Фронтенд

Клиентская часть представляет собой Single Page Application на React 19 с полной типизацией через TypeScript. Сборка осуществляется через Vite — быстрый инструмент с поддержкой Hot Module Replacement и оптимизацией бандла. Стилизация построена на Tailwind CSS v4 в связке с Vanilla CSS Design System для компонентов, требующих тонкой настройки, а анимации реализованы через Framer Motion.

Архитектура фронтенда следует методологии Feature-Sliced Design (FSD), которая разделяет код на слои: shared (общие утилиты), entities (бизнес-сущности), features (пользовательские сценарии), widgets (самостоятельные блоки UI) и pages (страницы приложения). Это обеспечивает модульность, переиспользуемость и упрощает навигацию в большой кодовой базе.

### 2.5 Состояние и запросы

Управление серверным состоянием осуществляется через TanStack React Query v5, который предоставляет кэширование запросов, автоматические ретраи при ошибках, пагинацию и инвалидацию кэша. Все сетевые запросы проходят через единую обёртку apiRequest в shared/api/http, что обеспечивает централизованную обработку ошибок, добавление заголовков авторизации и перехват ответов.

Локализация реализована через react-i18next с поддержкой русского и английского языков из коробки. Интерактивные элементы UI используют @dnd-kit для Kanban-драг-дропа, SunEditor для rich-text редактирования и Lucide Icons для иконографии.

### 2.6 Инфраструктура и деплой

Бэкенд развёрнут на платформе Fly.io в регионе Amsterdam в виде Docker-контейнера. Fly.io автоматически управляет репликацией, перезапуском упавших инстансов и распределением нагрузки. Фронтенд хостится на GitHub Pages — бесплатном CDN для статических сайтов, что обеспечивает глобальную доступность и низкую латентность.

CI/CD пайплайны реализованы через GitHub Actions и включают автоматическое тестирование, проверку типов TypeScript, сборку артефактов и деплой на целевые платформы. Ночные джобы выполняют резервное копирование базы данных и отправляют уведомления в Telegram-канал о статусе системы.

### 2.7 Мониторинг и обсервабилити

Для отслеживания здоровья системы используются несколько инструментов. Actuator health endpoints предоставляют информацию о состоянии приложения, подключении к БД и других компонентах. Prometheus-метрики собирают данные о производительности, количестве запросов и использовании ресурсов. UptimeRobot мониторит доступность endpoints и отправляет алерты при обнаружении проблем.

### 2.8 Коммуникации в реальном времени

Чат и уведомления работают поверх WebSocket через протокол STOMP с SockJS в качестве fallback-механизма. Авторизация подключений реализована на уровне топиков: пользователи могут подписываться только на каналы `/topic/chat/{userId}`, где userId соответствует их учетной записи. Это предотвращает подслушивание сообщений между пользователями.

### 2.9 Генерация документов

PDF-документы генерируются через связку Thymeleaf (шаблонизатор) и OpenHTMLtoPDF (рендерер), что обеспечивает полную поддержку кириллицы, сложной типографики и корпоративного брендинга. DOCX-документы создаются через poi-tl — библиотеку для программной работы с форматами Microsoft Office. DocumentGeneratorService предоставляет унифицированный интерфейс для генерации различных типов документов из шаблонов.

### 2.10 Тестирование

Бэкенд покрыт 74 unit-тестами на JUnit 5 и Mockito, обеспечивающими проверку критических сервисов и контроллеров. Тесты запускаются автоматически в CI/CD пайплайне и блокируют деплой при падении. Фронтенд использует Vitest для unit-тестирования компонентов и хуков.
