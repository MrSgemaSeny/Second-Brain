## 9. API и эндпоинты

### 9.1 Структура API

Все эндпоинты располагаются за контекстным путём /api и версионируются как /v1. Итоговые пути: /api/v1/{resource}. Swagger UI доступен в dev/staging окружениях по пути /swagger-ui.html (отключен в production).

Стандартные HTTP-методы используются по назначению:
- GET — получение данных (список или один ресурс)
- POST — создание ресурса
- PUT/PATCH — обновление ресурса
- DELETE — удаление ресурса

### 9.2 Формат ответов

Успешный ответ возвращает JSON:
```json
{
  "success": true,
  "data": { ... },
  "timestamp": "2026-08-07T10:30:00Z"
}
```

Ошибка возвращает JSON:
```json
{
  "success": false,
  "error": {
    "code": "TASK_NOT_FOUND",
    "message": "Задача с ID 123 не найдена"
  },
  "timestamp": "2026-08-07T10:30:00Z",
  "requestId": "req-uuid-123"
}
```

requestId связывает ошибку с логами для отладки.

### 9.3 Коды ошибок

ApiException с ErrorCode определяет тип ошибки:
- UNAUTHORIZED (401) — не аутентифицирован
- FORBIDDEN (403) — нет прав доступа
- NOT_FOUND (404) — ресурс не найден
- VALIDATION_ERROR (400) — ошибка валидации
- CONFLICT (409) — конфликт (дубликат email)
- RATE_LIMITED (429) — превышен лимит запросов
- INTERNAL_ERROR (500) — внутренняя ошибка сервера

### 9.4 Основные эндпоинты

**Auth Controller (/api/v1/auth)**
- POST /login — логин с email/password
- POST /register — регистрация нового пользователя
- POST /logout — логаут
- POST /refresh — обновление access-токена
- POST /google — OAuth2 Google login

**Two Factor Controller (/api/v1/2fa)**
- POST /setup — инициализация 2FA
- POST /verify — верификация TOTP
- POST /disable — отключение 2FA

**Tasks Controller (/api/v1/tasks)**
- GET / — список задач (фильтрация по статусу, клиенту, исполнителю)
- GET /{id} — детали задачи
- POST / — создание задачи
- PUT /{id} — обновление задачи
- DELETE /{id} — удаление задачи
- POST /{id}/subtasks — добавление подзадачи
- POST /{id}/comments — добавление комментария
- POST /batch/assign — массовое назначение

**Clients Controller (/api/v1/clients)**
- GET / — список клиентов
- GET /{id} — детали клиента
- POST / — создание клиента
- PUT /{id} — обновление клиента

**Invoices Controller (/api/v1/invoices)**
- GET / — список счетов
- GET /{id} — детали счёта
- POST / — создание счёта
- PUT /{id} — обновление счёта
- GET /{id}/pdf — скачать PDF

**Documents Controller (/api/v1/documents)**
- GET / — список документов
- GET /{id} — детали документа
- POST / — создание/загрузка документа
- DELETE /{id} — удаление документа
- GET /{id}/download — скачать файл

**Courses Controller (/api/v1/courses)**
- GET / — список курсов
- GET /{id} — детали курса
- POST /enroll/{id} — запись на курс
- GET /progress/{id} — прогресс по курсу

**Chat Controller (/api/v1/chat)**
- GET /contacts — список контактов
- GET /messages/{contactId} — история сообщений
- POST /send — отправка сообщения

### 9.5 Pagination

Списковые эндпоинты поддерживают пагинацию:
```
GET /api/v1/tasks?page=0&size=20&sort=createdAt,desc
```

Ответ содержит metadata:
```json
{
  "success": true,
  "data": [...],
  "pagination": {
    "page": 0,
    "size": 20,
    "totalElements": 150,
    "totalPages": 8
  }
}
```

### 9.6 Filtering

Фильтрация реализована через query-параметры:
```
GET /api/v1/tasks?status=OPEN&priority=HIGH&assignedToMe=true
GET /api/v1/invoices?fromDate=2026-01-01&toDate=2026-12-31&status=OVERDUE
```
