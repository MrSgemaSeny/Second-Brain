## 14. Регламент эксплуатации

### 14.1 Деплой

Деплой выполняется автоматически через GitHub Actions при push в main. Фронтенд деплоится на GitHub Pages, бэкенд — на Fly.io. Rollback выполняется через переключение на предыдущий Docker image на Fly.io или передеплой предыдущего commit на GitHub Pages.

### 14.2 Мониторинг

UptimeRobot проверяет endpoints каждые 5 минут. При недоступности отправляется алерт в Telegram. Логи приложения доступны через `flyctl logs`.

### 14.3 Резервное копирование

Ночной бэкап базы данных выполняется в 03:00 по UTC. pg_dump архивируется в gzip и сохраняется в GitHub Actions artifacts. Retention: 30 дней.

### 14.4 Восстановление

```bash
# Скачать бэкап из artifacts или хранилища
gunzip -c backup_2026-08-01.sql.gz | psql -h <host> -U postgres -d zhan_finance_db
```

### 14.5 Incident Response

**Сценарий A: CORS ошибки на WebSocket**
- Симптом: CORS policy и 404 на /ws/info
- Причина: Фронтенд обращается мимо контекста /api
- Действие: Проверить getWsEndpointUrl в http.ts — должен быть /api/ws

**Сценарий B: ChunkLoadError после деплоя**
- Симптом: 404 на JS-чанках при навигации
- Причина: Браузер закэшировал старый index.html
- Действие: Ctrl+F5 для очистки кэша

**Сценарий C: 429 Too Many Requests**
- Симптом: HTTP 429 от API
- Причина: Сработал rate limiter
- Действие: Подождать минуту или проверить частоту запросов

**Сценарий D: Flyway Checksum Error**
- Симптом: Приложение не стартует, checksum mismatch
- Причина: Изменение применённой миграции
- Действие: Создать компенсирующую миграцию. НИКОГДА не использовать flywayClean на production!

### 14.6 Дерево решений для критических ситуаций

1. Приложение не отвечает:
   - Проверить логи: `flyctl logs`
   - Проверить health endpoint
   - Перезапустить: `flyctl restart`

2. Ошибка подключения к БД:
   - Проверить статус PostgreSQL
   - Проверить credentials
   - Проверить firewall rules

3. Утечка данных:
   - Немедленно отключить compromised аккаунт
   - Проанализировать логи аудита
   - Уведомить затронутых пользователей
