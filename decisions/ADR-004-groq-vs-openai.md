# ADR-004: Использование Groq (Llama 3.3) вместо OpenAI для внутренних фич
_Дата: 2026-08-17_
_Статус: принято_

## Контекст
Выбор LLM провайдера для внутренних AI-механик в проектах (например, суммаризация резюме, парсинг сырого текста в JSON-структуры). Традиционный выбор — OpenAI (GPT-4o / GPT-4o-mini).

## Решение
Использовать API от **Groq** с моделями класса Llama (например, `llama-3.3-70b-versatile` или `llama3-8b-8192`) для задач трансляции, суммаризации и извлечения JSON.

## Причины
- **Экстремальная скорость:** LPU от Groq выдают от 300 до 800 токенов в секунду. Это позволяет выполнять AI-операции синхронно, не заставляя пользователя долго ждать (low latency).
- **Стоимость:** Значительно дешевле OpenAI при сопоставимом качестве для задач структурирования текста.
- **Strict JSON Mode:** Groq поддерживает `response_format: { "type": "json_object" }`, что критически важно для интеграции с нашим бэкендом (генерация строгих DTO).

## Последствия
- LLM Llama-3 может уступать GPT-4o в задачах со сложным "reasoning" (многошаговая логика, сложная математика). Для таких задач (если появятся) придется подключать OpenAI или Anthropic.
- В системный промпт *обязательно* нужно явно добавлять требование вернуть JSON, иначе API Groq вернет `400 Bad Request`.
