# ADR-018: Архитектура медиа-стриминга, Presigned URLs и WebVTT CORS Proxy

## 1. Контекст и проблематика
При проектировании мультимедийной стриминговой платформы (testCinema / INSIGHT) возникли две критические архитектурные проблемы доставки медиа-контента:
1. **Безопасность приватного объектного хранилища (MinIO S3):**
   Видеофайлы (MP4/HLS) и субтитры хранятся в приватных бакетах MinIO. Прямой публичный доступ к бакету отключен для предотвращения несанкционированного выкачивания контента и перегрузки хранилища.
2. **Браузерная CORS-блокировка субтитров (`<track>` WebVTT):**
   Согласно спецификации W3C HTML5, браузеры запрашивают дорожки субтитров (`<track src="...">`) с жесткими CORS-проверками даже для медиа-элементов с одного домена. Запрос субтитров напрямую из S3 по presigned URL часто блокируется браузерами из-за строгих `Access-Control-Allow-Origin` заголовков и различий в портах.
3. **Несоответствие форматов (SRT vs WebVTT):**
   Подавляющее большинство сторонних субтитров из OpenSubtitles поставляются в формате `.srt` с запятыми в миллисекундах (`00:00:01,000`), тогда как нативный HTML5 `<track>` требует строго спецификацию WebVTT (`WEBVTT` заголовок и точка `00:00:01.000`).

## 2. Рассмотренные альтернативы
- **Вариант А:** Сделать бакет MinIO полностью публичным и настроить CORS на стороне S3.
  - *Минусы:* Утечка контента, невозможность контроля доступа по JWT, отсутствие валидации прав пользователя.
- **Вариант Б:** Предварительная фоновая конвертация всех SRT в VTT на диске и раздача через Nginx.
  - *Минусы:* Дублирование дискового пространства, необходимость отдельного сервиса-конвертера.
- **Вариант В (Принятое решение):** Гибридный шлюз:
  1. Для тяжелого видеопотока — генерация короткоживущих presigned-ссылок MinIO (`/stream/{id}`).
  2. Для легковесных субтитров — потоковый Spring Boot Proxy (`/stream/{id}/subtitle`), который на лету конвертирует SRT в WebVTT и отдает поток с корректными заголовками `Content-Type: text/vtt; charset=utf-8` от имени основного API-домена.

## 3. Архитектурное решение
1. **Генерация Presigned URLs для видео:**
   Сервис `StreamService` формирует временный URL к объекту в MinIO через `minioClient.getPresignedObjectUrl(GetPresignedObjectUrlArgs.builder().method(Method.GET).bucket(...).expiry(60, TimeUnit.MINUTES).build())`. Ссылка живет ограниченное время и дает браузеру прямой канал к хранилищу без нагрузки на JVM бэкенда.
2. **On-the-Fly SRT to WebVTT Proxy:**
   Контроллер `StreamController.java` (`GET /stream/{id}/subtitle`) извлекает байты субтитров из хранилища и прогоняет через потоковый конвертер:
   - Добавление обязательного заголовка `WEBVTT\n\n`.
   - Замена таймкодов регулярным выражением: `(\d{2}:\d{2}:\d{2}),(\d{3})` на `$1.$2`.
   - Ответ клиенту отдается со статусом 200 OK, заголовками `Content-Type: text/vtt; charset=utf-8` и включенным CORS контроллера бэкенда.
3. **Безопасность:**
   Эндпоинты `/stream/**` открыты для чтения (`@PermitAll`), но сами идентификаторы фильмов валидируются, а прямой доступ к приватным ключам MinIO остается строго инкапсулирован внутри бэкенда.

## 4. Последствия и преимущества
- **Позитивные:**
  - 100% устранение CORS-ошибок при воспроизведении субтитров во всех современных браузерах.
  - Совместимость с любыми внешними SRT-файлами без необходимости их физической модификации в хранилище.
  - Разгрузка оперативной памяти и сетевого интерфейса бэкенда при передаче гигабайтных видеопотоков (прямой presigned стриминг из MinIO).
- **Компромиссы:**
  - Нагрузка на процессор при конвертации строк субтитров на лету (нивелируется их малым размером — до 100-200 КБ).
