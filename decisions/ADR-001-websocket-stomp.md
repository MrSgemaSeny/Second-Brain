# ADR-001: WebSocket через STOMP, не SSE
_Дата: 2026-08-07_
_Статус: принято_
_Проект: JF-1C_

## Контекст
Нужен реалтайм-чат в B2B CRM JF-1C с поддержкой ролей (ADMIN, EMPLOYEE, CLIENT, LEARNER, CURATOR, ADVISOR). Одно из ключевых требований — надежная двунаправленная связь для общения.

## Решение
Выбран STOMP поверх WebSocket, вместо Server-Sent Events (SSE) или Long Polling.

## Причины
- **Нативная поддержка:** Spring Boot имеет мощную "из коробки" поддержку WebSocket STOMP (модуль spring-websocket, spring-messaging).
- **Роутинг:** Легко добавить topic-based routing по ролям и ID пользователей (например, `/topic/chat/{userId}`).
- **Двунаправленность:** SSE предоставляет связь только от сервера к клиенту (unidirectional). Нам нужен полноценный bidirectional канал для чата без создания отдельных REST эндпоинтов для отправки сообщений, когда можно всё пустить по одному сокету.

## Последствия
- **Технические трудности на клиенте:** Проблемы с iOS Safari (браузер агрессивно рубит неактивные сокеты, ITP).
- **Масштабирование:** При деплое нескольких инстансов бэкенда потребуется Redis pub/sub брокер для синхронизации WebSocket сессий между узлами.
