# ADR-009: Многоуровневое ограничение частоты запросов (Rate Limiting) через Bucket4j и Caffeine Cache

## Статус
Принято (2026-08-27)

## Контекст
Платформа MrDevCourses предоставляет публичные эндпоинты аутентификации (вход/регистрация), ресурсоемкие операции вызова LLM AI-наставника и общие API эндпоинты курсов и прогресса.
Без рейт-лимитинга система уязвима к:
1. Brute-force атакам и credential stuffing на эндпоинтах логина.
2. Исчерпанию квот внешнего AI API (Groq) и финансовым затратам при злоупотреблении AI-чатом.
3. DDoS и скрейпингу контента курсов.

## Решение
Реализовать Token Bucket алгоритм на уровне Servlet Filter с использованием библиотеки `io.github.bucket4j:bucket4j-core:8.10.1` и локального in-memory кэша `com.github.benmanes.caffeine:caffeine:3.1.8`.

### Архитектура и уровни ограничений (Tiers):
1. **AUTH Tier** (`/v1/auth/**`):
   - Ключ: IP-адрес (`ip:<client_ip>`).
   - Квота: 10 токенов на 15 минут (`refillIntervally`).
2. **AI Tier** (`/v1/ai/**`):
   - Ключ: User ID авторизованного студента (`user:<id>`) с fallback на IP.
   - Квота: 5 токенов в минуту.
3. **GENERAL Tier** (`/v1/**`):
   - Ключ: User ID или IP.
   - Квота: 60 токенов в минуту.

### Стандартизация ответов:
- Заголовки: `X-RateLimit-Remaining` (количество оставшихся токенов) и `Retry-After` (секунды до пополнения).
- При исчерпании лимита: HTTP статус `429 Too Many Requests` со структурированным JSON телом ошибки.

## Последствия
- Положительные:
  - Нулевая зависимость от внешнего Redis на текущем этапе, минимальный оверхед по памяти (Caffeine `maximumSize=50_000`, `expireAfterAccess=1h`).
  - Мгновенная защита от перегрузок и ботов.
  - Легкая миграция на Redis/Redisson в будущем при переходе к распределенному кластеру бэкенда.
