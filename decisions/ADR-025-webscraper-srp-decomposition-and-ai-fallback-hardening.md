# ADR-025: Декомпозиция монолитного WebScraperService по SRP и исключение фиктивных данных-заглушек

## Статус
Принято (Accepted)

## Дата
2026-09-16

## Контекст и проблематика
В рамках аудита архитектуры MeDev v2.0 (P2 Architecture) класс `WebScraperService` представлял собой классический "God Service" (350+ строк кода):
1. Класс совмещал шесть разнородных обязанностей: валидацию безопасности сетевых URL, Rate Limiting через Redis, работу с публичным REST API HeadHunter, прямой парсинг DOM через Jsoup для LinkedIn/Habr/HH, LLM-экстракцию через Groq и сборку DTO.
2. Тестируемость монолита была низкой, изменение логики парсинга одного сайта создавало риски поломки валидации безопасности.
3. При сбоях парсинга или отсутствии данных в профиле пользователя сохранялись фиктивные строки-плейсхолдеры ("Company", "Software Engineer", "University"), загрязнявшие базу данных и вводившие пользователей в заблуждение.

## Принятые решения

### 1. Декомпозиция на 5 специализированных SRP-компонентов
`WebScraperService` переведен в роль тонкого фасада/координатора, делегирующего работу независимым сервисам:
1. `UrlSecurityValidator` — проверка безопасности схемы, портов, DNS-резолвинга и блокировка SSRF.
2. `ScrapeRateLimiter` — контроль частоты запросов на парсинг по пользователям в Redis.
3. `HhVacancyClient` — интеграция с публичным REST API `api.hh.ru/vacancies/{id}` и сборка структурированных данных.
4. `GenericPageFetcher` — безопасная загрузка HTML-страниц через Jsoup с проверкой каждого редиректа и обработкой селекторов для LinkedIn, Habr и HeadHunter.
5. `AiJobExtractor` — резервное LLM-извлечение вакансий из неструктурированного текста страницы через Groq API.

### 2. Ликвидация фиктивных данных и переход на Nullable-семантику
- Все синтетические заглушки (`"Company"`, `"Software Engineer"`, `"University"`) удалены из сервисов профиля и AI-онбординга.
- Неизвестные или отсутствующие поля сохраняются как `null` / `Optional.empty()`.
- В UI и валидаторах явно поддерживаются опциональные поля без принудительного заполнения мусорными строками.

## Последствия
- Положительные:
  - Коэффициент сцепления (Coupling) снижен, связность (Cohesion) компонентов повышена до 100% SRP.
  - Каждый компонент получил автономный модульный тест (`WebScraperDecompositionTest`, `UrlSecurityValidatorTest`, etc.).
  - База данных защищена от мусорных плейсхолдеров.
