# ADR-011: DESIGN.md как контракт дизайн-токенов (Design Tokens Contract)

## Статус
Принято (Accepted) — 2026-08-28

## Контекст
При разработке UI силами AI-агентов без строгого контракта возникает "AI Slop" — хаотичные размеры шрифтов (6+ уровней), необоснованные градиенты, чрезмерные тени, произвольные радиусы скругления (`rounded-2xl`, `rounded-3xl`) и декоративные Bento-сетки, ломающие иерархию и плотность технического контента. Для LMS и SaaS-платформ разработчиков требуется строгая, чистая, техническая эстетика, напоминающая современную IDE.

## Решение
Ввести обязательный файл `DESIGN.md` в корне каждого фронтенд-модуля как неизменяемый контракт токенов:
1. **Типографическая шкала:** Строго 4 уровня (`text-xs` 12px, `text-sm` 14px, `text-base` 16px, `text-lg/xl` 18-20px). Иерархия строится через насыщенность (`font-medium` для текста, `font-semibold` для заголовков) и цвет (`zinc-100` / `zinc-300` / `zinc-400`), а не раздувание размеров.
2. **Палитра:** 
   - Base Surface: `#0a0a0c`
   - Elevated Surface (карточки): `#18181b` (zinc-900) с контрастным соотношением > 14:1.
   - Borders: `rgba(255, 255, 255, 0.08)` с тонким `inset-highlight` `shadow-[inset_0_1px_0_rgba(255,255,255,0.04)]`.
   - Запрет нефункциональных неоновых/циановых акцентов: основной акцент нейтральный белый `#ffffff` / `zinc-200`.
3. **Радиус:** Строгий компактный радиус `rounded-sm` (2px) или `rounded` (4px).
4. **Сетка и Layout:** Функциональная колоночная сетка без надуманного "Bento ради Bento". Высота и позиция блоков диктуются исключительно структурой данных.

## Последствия
- **Положительные:** Полное устранение визуального шума (deslop), единообразие интерфейсов на всех экранах, доступность WCAG AA, высокая скорость восприятия кода и материалов.
- **Отрицательные:** Необходимость ручного аудита верстки на соответствие токенам перед сдачей задач.
