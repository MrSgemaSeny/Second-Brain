# ADR-005: Security Baseline for Production (Migration from MVP)

## Статус
**Принято** (Август 2026)

## Контекст
В ходе аудита безопасности бэкенда ZhanFinance были выявлены уязвимости, типичные для архитектуры раздельных SPA и API на этапе MVP. Решения, принятые ради скорости разработки (например, `SameSite=None` для обхода кросс-доменных политик, передача JWT в URL для сокетов, упрощенная проверка загружаемых файлов, хардкод дефолтных значений для секретов), стали неприемлемыми при переходе приложения в стадию Production-ready на Fly.io.

## Решение
Мы отказываемся от MVP-компромиссов в пользу строгих Production Security стандартов:

1. **Отказ от дефолтных секретов:** Приложение должно реализовывать подход Fail-Fast. Никаких дефолтных `@Value` для критических ключей (например, Google Client ID, JWT Secret, Telegram Token). Без этих переменных приложение должно падать на старте.
2. **CSRF и SameSite:** Полный отказ от ослабленного `SameSite=None` (кроме случаев абсолютной необходимости с внедрением синхронизирующего CSRF токена). При размещении API и Frontend на одном домене (включая поддомены) куки должны иметь флаг `SameSite=Lax` или `SameSite=Strict`.
3. **Безопасные WebSockets:** Исключительно передача токенов через заголовки STOMP CONNECT фрейма. Передача токена через Query Parameters (`?token=`) запрещена из-за риска утечки через логи.
4. **Валидация файлов:** Переход от проверки расширений (`.endsWith(".pdf")`) к обязательному анализу Magic Bytes с помощью Apache Tika для всех публичных загрузок файлов (включая аватарки). Внедрение жестких лимитов по размеру файла (max-file-size).
5. **Защита от спуфинга IP:** При использовании Rate Limit фильтров полагаться на `request.getRemoteAddr()`, а не на заголовки (`Fly-Client-IP`), если нет строгой гарантии очистки заголовков балансировщиком. 
6. **Санитизация CSV:** Обязательное экранирование символов `=`, `+`, `-`, `@` при генерации CSV-файлов для защиты от Formula Injection в Excel/LibreOffice.

## Последствия (Следствия)
- **Положительные:** Кардинально снижается риск XSS/CSRF атак, угона сессий, обхода лимитов и заливки вредоносного ПО на сервер. Бэкенд становится Enterprise-grade.
- **Отрицательные:** Возможно усложнение конфигурации CORS при локальной разработке. Разработчикам потребуется обязательно настраивать `.env` перед локальным запуском (Fail-fast).
