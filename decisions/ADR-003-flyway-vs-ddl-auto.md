# ADR-003: Исключительное использование Flyway для миграций БД
_Дата: 2026-08-17_
_Статус: принято_

## Контекст
Управление схемой базы данных в Spring Boot приложениях. Разработчики часто полагаются на `spring.jpa.hibernate.ddl-auto=update` для быстрого прототипирования.

## Решение
Полный отказ от `ddl-auto=update` во всех энвайронментах (даже на локалке). С самого старта проекта схема БД управляется исключительно через **Flyway** (или Liquibase). 
Значение `spring.jpa.hibernate.ddl-auto` всегда устанавливается в `validate` или `none`.

## Причины
- **Предсказуемость:** Точно известно, какие скрипты и в каком порядке были применены. Нет магии ORM.
- **Безопасность данных:** `ddl-auto=update` не умеет безопасно переименовывать колонки (он удалит старую и создаст новую, уничтожив данные) или менять типы данных.
- **Управление версиями:** Схема БД версионируется вместе с кодом в Git, обеспечивая Single Source of Truth.
- **Идентичность сред:** Локальная БД, staging и production имеют идентичную структуру.

## Последствия
- Снижается скорость внесения мелких правок на ранних этапах прототипирования (приходится писать SQL скрипты `V1__...sql`).
- Требуется строгое соблюдение нейминга миграций. Запрещается изменять уже примененные миграции (только создавать новые).
