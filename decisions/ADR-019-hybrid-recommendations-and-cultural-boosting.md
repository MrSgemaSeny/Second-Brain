# ADR-019: Гибридный рекомендательный движок и культурный бустинг (REC-AI)

## 1. Контекст и проблематика
При создании контентной платформы с акцентом на локальный рынок (testCinema / INSIGHT) стандартные рекомендательные системы (чистый Collaborative Filtering или простой поиск по похожим жанрам) сталкиваются с двумя проблемами:
1. **Проблема холодного старта (Cold Start):**
   Новые фильмы или пользователи без истории оценок не получают адекватных рекомендаций в чисто коллаборативных моделях (Matrix Factorization / SVD).
2. **Задача поддержки отечественного кинематографа:**
   Необходимо приоритизировать показ казахстанских фильмов без ущерба для релевантности и без превращения ленты в навязчивый каталог исключительно локального контента (риск оттока пользователей).

## 2. Архитектурное решение: Гибридная модель REC-AI
Принято решение реализовать многоуровневый рекомендательный сервис на Python FastAPI (`rec_ai`) с прямым доступом к общей реплике PostgreSQL:

### 2.1. Контентная модель (Content-Based) с искусственным взвешиванием
Формируется обогащенная строка описания каждого фильма с искусственным повышением веса ключевых признаков:
$$\text{Content} = 3 \times \text{Genre} + 2 \times \text{Director} + \text{Description} + \text{Actors}$$
- Векторизация: `TfidfVectorizer(ngram_range=(1, 2), max_features=8000)`.
- Расчет косинусного сходства: $N \times N$ матрица косинусных расстояний рассчитывается при старте сервиса и кэшируется в RAM для получения похожих фильмов за $O(1)$.

### 2.2. Коллаборативный профиль вкусов на основе досмотра (Watch Completion)
Вкусовой вектор пользователя формируется как взвешенная сумма векторов просмотренных картин из таблицы `watch_history`:
- Фильм досмотрен полностью (`completed = true`): вес $w = 2.0$.
- Фильм просмотрен частично: вес масштабируется линейно $w = 0.5 + \min(\text{seconds} / 7200, 1.0)$.
- Обогащение неявными сигналами:
  - Клики по карточкам (`movie_clicks`): вес $0.3$.
  - Жанровые интенты из поисковых запросов (`search_logs`).
  - Предпочтение субтитров (`subtitle_events` с `lang='kk'` дает буст к картинам с казахской дорожкой).

### 2.3. Алгоритм культурного бустинга и Diversity Guard
Для поддержки казахстанского кино рассчитывается адаптивный коэффициент:
- Если доля просмотров KZ-фильмов пользователем $\ge 50\% \implies \text{Boost} = 1.8$;
- Доля от $20\%$ до $50\% \implies \text{Boost} = 1.4$;
- Доля $< 20\% \implies \text{Boost} = 1.15$ (ненавязчивое предложение).
- **Diversity Guard (Ограничитель однообразия):** Функция `_apply_kz_ratio` извлекает расширенный пул кандидатов ($3 \times N$), а затем балансирует финальную выдачу так, чтобы доля отечественного кино не превышала **35%**, гарантируя разнообразие каталога.

### 2.4. Реалтайм-метрики и расчет CTR
Каждый показ рекомендации фиксируется в таблице `recommendation_impressions(user_id, movie_id, strategy, position, clicked, shown_at)`. Клик по карточке обновляет `clicked_at`, позволяя в реальном времени сравнивать CTR различных алгоритмических стратегий в админ-панели.

## 3. Последствия и преимущества
- **Позитивные:**
  - Высокая релевантность рекомендаций с первого дня (контентная матрица отвечает мгновенно даже при нуле оценок).
  - Сбалансированное и научно обоснованное продвижение локального кинематографа.
  - Прозрачная воронка конверсии благодаря прямому трекингу показов и кликов по стратегиям.
- **Компромиссы:**
  - Требуется периодический фоновый пересчет матрицы при добавлении новых фильмов (`POST /api/recommendations/retrain`).
