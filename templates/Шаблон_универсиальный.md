---

## КАК ПОЛЬЗОВАТЬСЯ ЭТИМ ФАЙЛОМ

1. Копируешь файл в корень нового репозитория (`PROJECT_LIFECYCLE.md`).
2. Заполняешь `PROJECT STATUS BLOCK` внизу файла.
3. Кидаешь файл AI в начале сессии. AI читает STATUS BLOCK → находит фазу в списке ниже → действует по чеклисту этой фазы.
4. Статус подфазы меняешь вручную: `[ ]` не начато / `[~]` в процессе / `[x]` готово.
5. Трек (TRACK) определяется один раз в Фазе 1 и не меняется на середине проекта.

**TRACK SIMPLE** — пет-проект, внутренний инструмент, MVP для себя/друзей, без цели продавать многим клиентам.
**TRACK FULL** — продукт, который планируется продавать как SaaS нескольким компаниям/пользователям (пример: Жан Финанс).

Пункты с пометкой `[FULL ONLY]` пропускаются в TRACK SIMPLE. Пункты без пометки обязательны в обоих треках.

## РАСШИРЕНИЕ ШАБЛОНА ПОД НОВЫЕ ТИПЫ ПРОЕКТОВ

Когда появится новый тип проекта (мобильное приложение, телеграм-бот и т.п.):
1. Структура фаз (1-6) остаётся той же — это универсальный жизненный цикл.
2. Добавляется новый блок ниже с пометкой `## STACK EXTENSION: <тип>`.
3. Внутри блока переопределяются только пункты, специфичные для стека (например, для телеграм-бота Фаза 1.2 будет про Bot API вместо React, а Фаза 1.6 не будет содержать домен).
4. Общие для всех стеков пункты (роли, security, тесты, мониторинг) не дублируются.
