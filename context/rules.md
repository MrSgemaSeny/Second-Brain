# Правила системы Brain's Protocol

##  ГЛАВНОЕ ПРАВИЛО СИСТЕМЫ

```
ТЕСТЫ ПРОШЛИ → AI ПИШЕТ В BRAIN'S PROTOCOL → GIT PUSH

Никогда наоборот. Никогда без лога.
(Подкреплено хардкорным Lifecycle Hook `enforce-workflow.ps1` и `stop-check-commits.ps1` в Antigravity, который физически блокирует git push и завершение хода при отсутствии записи в журнале или незакоммиченных файлах в репозитории).
```

## Протокол сессии (что AI делает)

**ДО НАЧАЛА:**
1. Читает `context/me.md`
2. Читает `context/projects.md`
3. Читает `context/rules.md`
4. Читает `context/prompts_for_ai.md`
5. Сканирует `knowledge/` на предмет релевантных архитектурных паттернов
6. Читает индексный файл `projects/{active-project}/index.md` (и нужные модули)
7. Читает последний `journal/YYYY-MM-DD/{project}.md`
8. Подтверждает готовность

**ВО ВРЕМЯ РАБОТЫ:**
- Работает с полным контекстом Second Brain
- Соблюдает архитектурные ограничения проекта
- Любое изменение UI начинает со сверки с `DESIGN.md` (токены, 4-уровневая типографика, отсутствие deslop)

**ПОСЛЕ ЗЕЛЁНЫХ ТЕСТОВ:**
1. Создаёт/открывает `journal/YYYY-MM-DD/{project}.md`
2. Записывает по шаблону session-log.md (Добавлено, Изменено, Удалено, Проблемы, Тесты)
3. Проверяет нужно ли обновить `projects/{project}/...`
4. Экстрагирует ценный опыт (хаки, багфиксы, тюнинг) в новые файлы `knowledge/`
5. Проверяет и обновляет `knowledge/knowledge-index.md`, если были добавлены новые знания
6. Проверяет нужно ли дополнить `prompts_for_ai.md`
7. ВЫПОЛНЯЕТ GIT PUSH

## Стандарт `.agents` Lifecycle Hooks для всех проектов

Каждый проект в `new_world` обязан содержать директорию `.agents/` со следующей конфигурацией `hooks.json`:
- **PreInvocation (`pre-invocation.ps1`)**: Автоматически подгружает на 1-м шаге сессии `.agents/CONTEXT.md` и ключевые файлы Second Brain (`me.md`, `projects.md`, `rules.md`).
- **PreToolUse (`safety-gate.ps1`)**: Блокирует использование неэффективных CLI-утилит чтения (`cat`, `grep`, `sed`, `ls`, `head`, `tail`) и деструктивные git-команды (`push --force`, `reset --hard`), форсируя использование нативных инструментов Antigravity.
- **PreToolUse (`enforce-workflow.ps1`)**: Перехватывает вызов `git push` и проверяет наличие отчета в `Brain's protocol - second brain/journal/` с поддержкой 24-часового плавающего окна.
- **Stop (`stop-check-commits.ps1`)**: Проверяет `git status --porcelain` в основном проекте и Second Brain. Возвращает `decision: continue`, пока все изменения не закоммичены.

## Правила дизайна (DESIGN.md-first & Deslop)

- **Перед любым изменением UI:** Сначала проверяется `DESIGN.md` проекта (или создается по шаблону токенов).
- **Типографика:** Строго 4 уровня (`text-xs`, `text-sm`, `text-base`, `text-lg/xl`). Иерархия выстраивается через `font-medium`/`font-semibold` и цвет текста (`zinc-100`, `zinc-300`, `zinc-400`), а не раздуванием размеров.
- **Палитра:** `#0a0a0c` base, `#18181b` cards/surfaces, границы `rgba(255,255,255,0.08)`. Запрещен визуальный шум, градиентный мусор и необоснованный bento-grid.
- **Интерактивность:** Фокус-ринги (`ring-2 ring-white/20`), accessibility WCAG AA, ховеры 150ms `ease-out`.

## Правила разработки (которые AI никогда не нарушает)

- **НИКОГДА** не менять применённые Flyway миграции
- **НИКОГДА** не хардкодить секреты в коде
- **НИКОГДА** `ddl-auto=update` в продакшене
- **НИКОГДА** `@PostConstruct` для DB операций — только `@EventListener(ApplicationReadyEvent.class)`
- **НИКОГДА** не использовать терминальные команды (типа `echo >>`, `cat` или `Add-Content`) для редактирования и добавления текста в файлы. Использовать только нативные инструменты редактирования.
- Тесты перед пушем — всегда
- FSD на фронтенде — всегда
- Security в архитектуре с первого дня

## Приоритеты при конфликте решений

```
Security > Correctness > Performance > Code Cleanliness
```


## Правила наполнения базы знаний (knowledge/)

**Что реально стоит туда класть**
Не всё подряд. Добавляй только то, что:
- решило реальную проблему в твоих проектах
- ты будешь искать снова через 3 месяца
- AI без этого даст плохой совет

Например:
- Spring Security — JWT rotation + revocation паттерны
- Flyway — edge cases при rollback миграций
- React Query — invalidation стратегии при оптимистичных обновлениях
- Fly.io — deploy pipeline, zero-downtime, secrets management
- PostgreSQL — RLS паттерны

**Что не стоит класть**
- Официальную документацию — AI её и так знает.
- Туториалы "как установить X" — это не знание, это инструкция.
- Всё, что устаревает быстрее, чем ты открываешь заметку.

**Работа с PDF и внешними материалами**
- **Самый простой способ:** дать PDF агенту (например, Claude Code) с промптом: *"Прочитай этот PDF. Извлеки ключевые идеи, паттерны и практики релевантные для Java/Spring Boot разработчика. Запиши в /knowledge/название-темы.md в формате Zettelkasten: суть, когда применять, примеры, ссылки на связанные заметки."*
- **Книги по архитектуре:** не пересказывай целиком, извлекай только решения, релевантные текущему масштабу.
- **Статьи и гайды:** либо целиком в `raw/`, либо сразу дистиллированно в `knowledge/`.
- **Собственные заметки (курсы/конференции):** самое ценное, так как содержат твой контекст и твои вопросы.
