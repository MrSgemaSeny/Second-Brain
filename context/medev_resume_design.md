# MeDev: Концепция дизайна резюме (Resume Design Vision)
_Обновлено: 2026-08-13_

## Суть проблемы
Текущие шаблоны (типа классики 2015 года) структурно правильны, но ощущаются как простой "data dump". В них есть информация, но нет эстетики и характера. 
Чтобы MeDev стал **генератором резюме, на которые люди ссылаются как на референс**, нужен радикальный пересмотр визуальной части. Резюме должно показывать не только *что* сделал разработчик, но и *как* он мыслит. Дизайн — это коммуникация качества.

## Ключевые идеи для новых шаблонов

1. **Editorial / Журнальный layout**
   - Газетная сетка, обилие "воздуха" (whitespace) вместо линий. 
   - Крупное имя (48-64pt, bold serif, например Playfair Display).
   - Теглайн в одну строку (например, *«Full-Stack Engineer · Kazakhstan»*).
   - Опыт: дата слева узкой колонкой, текст справа широкой.

2. **Тёмная тема (Dark Mode) для PDF**
   - Графитовый фон (`#1a1a1a`), светло-серый текст (`#e5e5e5`).
   - Один акцентный цвет (охра, медь, оливковый).
   - Обязательно: `@media print` с инверсией цветов для ч/б печати без потери читаемости.

3. **ASCII / Terminal Aesthetic**
   - Моноширинный шрифт (JetBrains Mono, SF Mono).
   - Оформление под код/терминал: Имя как `<h1>`, скиллы как JSON-объект.
   - Опыт работы как `git log --oneline`. Контакты как переменные окружения (`LOCATION=Almaty, KZ`).

4. **Визуальный Timeline**
   - Опыт работы оформлен горизонтальной или вертикальной линией с точками/узлами вместо классических буллитов. Даты вынесены к узлам. Тонкая акцентная линия для PDF.

5. **Продуктовые карточки проектов**
   - Проекты представлены как карточки (с тонкой рамкой 1px), а не списком.
   - Структура: Название (bold), 2 строки описания, теги технологий (pill'ы).
   - Сетка: до 3 проектов в ряд на веб-версии, на PDF — строгая геометрия.

6. **Skill Tags (без прогресс-баров)**
   - Отказ от неинформативных шкал "знания языка".
   - Использование категорий (Core, Proficient, Familiar), облака тегов (частые навыки крупнее) или минималистичной точечной шкалы (●●●●○).

7. **Hero-section на первой странице**
   - Обложка резюме: фото/аватар, крупное имя, 3 главные метрики (например, *4 production projects · 50k+ LOC · 2 years*), QR-код. 
   - Идеально как "визитка" на первую страницу, детали на второй.

8. **Асимметричная сетка 1:2**
   - Динамичный layout: Левая колонка (35%) с контактами/скиллами, правая (65%) с опытом и проектами. 
   - Визуальный якорь: смещение начала колонок для создания динамики.

9. **Markdown-native дизайн**
   - Стиль идеального README: `# Заголовки`, код-блоки для технологий.
   - Идеальная верстка, отступы, шрифты, но родная для разработчика семантика.

10. **Data-first верхняя часть (Интеграция с GitHub)**
    - Панель реальных метрик вместо скучного summary.
    - Коммиты за год, топ-3 языка (цветовые полоски GitHub-стиля), stars/forks (берутся из GitHub API). Доказательство того, что разработчик *пишет* код.

11. **Секция «Featured Project»**
    - Фокус на одном главном проекте (выделяется на половину страницы). 
    - Остальные идут списком/мельче. Создает вау-эффект главного достижения.

12. **Swiss / International Typographic Style**
    - Строгий минимализм: шрифты Inter/Geist. Черный, белый + 1 яркий акцент.
    - Выравнивание по базовой сетке 4pt. Огромный контраст между заголовками и текстом (48pt vs 9pt).

13. **QR-коды как графический объект**
    - Использование QR на GitHub/LinkedIn как элементов дизайна (красивые квадратные паттерны), интегрированных в композицию.

14. **Симбиоз Web и PDF**
    - Веб-версия — это интерактивный сайт (с анимацией печати, hover-эффектами).
    - PDF — статичный, но идентичный по дизайну экспорт ("на печать").

15. **Именованные цветовые темы**
    - Использование узнаваемых разработчиками палитр: *Tokyo Night*, *Gruvbox*, *Nord*, *Monokai*.

## Итог
Новые шаблоны должны сместить фокус с "базы данных" на "продукт". Мы создаем инструмент, который выдает премиальный, узнаваемый результат.
