# Архитектурный паттерн: AI Smart Merge (Умное слияние данных)

## Проблема
При парсинге данных из разных источников (например, загруженный пользователем PDF и извлеченный по API профиль GitHub) часто возникает конфликт.
Если просто отдать ИИ команду "сгенерируй профиль из этих данных", он склонен к **галлюцинациям**, потере важных дат или выдумыванию навыков, которых нет у пользователя. 

## Решение: Разделение Source of Truth + Smart Merge

Паттерн "Smart Merge" подразумевает строгое распределение ролей для каждого источника данных и передачу этих ролей в системный промпт LLM.

### 1. Определение Source of Truth (SoT)
- **GitHub API (или другой API):** Является абсолютным источником правды для **Стека технологий** и **Проектов**. LLM не имеет права выдумывать языки, которых нет в GitHub-снапшоте.
- **PDF-Резюме:** Является абсолютным источником правды для **Дат (начала/конца работы)**, **Названий компаний** и **Учебных заведений**.

### 2. Подготовка данных (Бэкенд)
Перед тем как отправлять данные в LLM (например, Groq), мы собираем их в единый структурированный контекст.
- Делаем асинхронные/параллельные вызовы (`Flux.flatMap`) к API (например, вытягиваем языки и `README.md` репозиториев).
- Читаем текст из PDF.
- Формируем JSON-снапшот текущего состояния.

### 3. Системный промпт (The Smart Merge Rule)
Мы передаем LLM четкую инструкцию (пример):
> "Ты должен слить данные из `PDF_TEXT` и `GITHUB_SNAPSHOT`. 
> ПРАВИЛО 1: Даты, места работы и образование брать ТОЛЬКО из PDF. Если в PDF даты нет, ставь null. НЕ ВЫДУМЫВАЙ ДАТЫ.
> ПРАВИЛО 2: Стек технологий и навыки брать в первую очередь из GitHub. Обогати описание опыта работы технологиями из GitHub."

### Преимущества
- Полностью исключает галлюцинации LLM в критичных полях (даты, названия компаний).
- Гарантирует целостность данных.
- Сохраняет "живой" язык и улучшает описание опыта, подтягивая реальный код (README) из GitHub.

### Использование в проектах
- **MeDev**: При загрузке резюме пользователем, бекенд берет последний `GithubSnapshot` и комбинирует его с текстом PDF для выдачи идеального `ProfileDto`.
