# Наблюдаемость: Мониторинг, метрики и алерты (Production Observability)

Инженерное руководство по настройке метрик, управлению памятью JVM и настройке алертов.

---

## 1. Алерты в Grafana и Prometheus: Относительные пороги и задержка (Hysteresis)

### 1.1. Проблема абсолютных порогов
Настройка алерта на абсолютное значение (например, `jvm_memory_used_bytes{area="nonheap"} > 100MB`) гарантированно приводит к ложным срабатываниям (Alert Fatigue) при естественном масштабировании или стартовом прогреве системы.

### 1.2. Решение: Относительные пороги и интервал удержания (`for: 5m`)
1. Использование относительных процентов от выделенного лимита:
   ```promql
   (jvm_memory_used_bytes{id="Metaspace"} / jvm_memory_max_bytes{id="Metaspace"}) > 0.85
   ```
2. Включение задержки срабатывания (`for: 5m`):
   Кратковременные всплески нагрузки или фазы инициализации не вызывают отправку уведомлений дежурному инженеру. Алерт отправляется строго тогда, когда порог превышен непрерывно в течение 5 минут.

## 2. Мониторинг памяти JVM Metaspace в Spring Boot

### 2.1. Физика прогрева Metaspace
Metaspace хранит метаданные классов, структуры методов, пулы констант и сгенерированный байткод.
В Spring Boot 3 под первой высокой нагрузкой (например, при стресс-тестах Artillery) происходит массовая генерация:
- CGLIB динамических прокси для `@Transactional` и `@PreAuthorize` сервисов.
- Jackson-сериализаторов и рефлексивных дескрипторов для DTO.
- Hibernate Type definitions и AST-планов запросов.

### 2.2. Эффект плато
Расход Metaspace быстро растет с 60–70 MB до 120–130 MB, после чего наступает стабилизация (плато). Это штатное поведение JVM, а не утечка памяти (Memory Leak).

### 2.3. Рекомендованный бюджет памяти для контейнеров (Fly.io / Render)
```properties
-XX:MaxMetaspaceSize=256m
-XX:MetaspaceSize=96m
-Xmx384m
-Xms256m
```
Фиксация `-XX:MaxMetaspaceSize=256m` предотвращает неконтролируемое разрастание native-памяти за пределы cgroup-лимита контейнера (OOM Kill).

## 3. Spring Boot Actuator: Безопасность и разграничение доступа

### 3.1. Разделение уровней доступа к Actuator
- `/actuator/health`: **Публичный доступ** (Liveness/Readiness проверки контейнерного оркестратора Fly.io / Kubernetes / UptimeRobot). Не должен содержать паролей, имен БД или подробных сведений об инфраструктуре (`management.endpoint.health.show-details=never`).
- `/actuator/metrics`, `/actuator/prometheus`: **Строго закрытый доступ** (только роль `ADMIN` или внутренний порт). Запрещено публиковать в открытый доступ, так как это раскрывает топологию памяти, сетевые задержки и статистику базы данных.

### 3.2. Настройка Spring Security
```java
http.authorizeHttpRequests(auth -> auth
    .requestMatchers("/actuator/health").permitAll()
    .requestMatchers("/actuator/**").hasRole("ADMIN")
);
```
