# Нагрузочное тестирование и кэширование (Уроки MeDev)

**Дата:** 2026-08-25
**Контекст:** Проведение боевого нагрузочного тестирования (Chaos Engineering) на бесплатном инстансе Render (512MB RAM, 0.1 CPU).

## 1. Суровая реальность HikariCP
Приложение на Spring Boot по умолчанию открывает пул из 10 соединений с базой данных (HikariCP).
Если на публичный эндпоинт (например, `/api/v1/portfolio/:username`) прилетает спайк из 100 запросов в секунду (RPS):
- Первые 10 запросов захватывают коннекты к БД.
- Из-за слабого CPU на бесплатном сервере, запросы с JOIN-ами (опыт, навыки, проекты) выполняются относительно долго (сотни миллисекунд).
- Остальные 90 запросов встают в очередь.
- Очередь не резиновая. Если соединение не выдается за `connectionTimeout` (по умолчанию 30 секунд), HikariCP выбрасывает `SQLTransientConnectionException`, и клиент получает `500 Internal Server Error` или таймаут.

**Вывод:** Бесплатный сервер падает не от нехватки памяти (OOM), а от нехватки соединений к базе данных. JVM и Spring Boot очень живучи.

## 2. Doc/Code Mismatch (Слепая зона кэширования)
Внешнее ревью кода часто смотрит на структуру поверхностно.
Например, ревьюер посоветовал добавить `@Cacheable` на `ProfileService.getByUserId`. 
Это было сделано, но тест показал, что пул БД всё равно исчерпывается.
**Причина:** Публичный контроллер `PortfolioController` использует собственный сервис `PortfolioService`, который напрямую вызывает методы репозитория (`profileRepository.findByUserId`), минуя закешированный `ProfileService`.
**Вывод:** Кэшировать нужно максимально близко к контроллеру, агрегирующему данные для клиента (в данном случае `PortfolioService.getPublicProfile`).

## 3. Правила Chaos Engineering
1. Нагрузочное тестирование на `localhost` бессмысленно для выявления инфраструктурных ограничений. Оно покажет только мощность твоего локального процессора (который выдержит 10 000 RPS).
2. Запускать `k6` или `artillery` на боевом сервере (Production) без явного согласования — это халатность. Всегда должен быть задан вопрос: "Бьем по проду или по реплике (Staging)?"
3. Если бьешь по проду, выбирай безопасные Read-Only эндпоинты, чтобы не положить платежи (Stripe/Kaspi) и не сжечь лимиты внешних API (Groq AI).

## 4. Инструментарий
Для быстрого e2e теста на Windows/Node.js без глобальных установок идеально подходит Artillery:
```bash
npx artillery run test.yml
```
Пример `test.yml`:
```yaml
config:
  target: 'https://backend.com'
  phases:
    - duration: 10
      arrivalRate: 5
    - duration: 20
      arrivalRate: 10
      rampTo: 50
    - duration: 10
      arrivalRate: 100
scenarios:
  - name: 'Public Load'
    flow:
      - get:
          url: '/api/v1/portfolio/username'
```
