## Урок 1: Архитектура Full-Stack проекта (Трекер денег)

### 1. Вступление: что мы строим и зачем
Сегодня мы начинаем разработку полноценного Full-Stack веб-приложения — **«Трекер денег» (Money Tracker)**.
В реальной разработке проекты не пишут в одном файле. У тебя будет архитектура уровня продакшена, но понятная и без лишней перегрузки:
1. **Frontend (клиент)** — интерфейс в браузере, где пользователь видит баланс, графики расходов и форму добавления трат.
2. **Backend (сервер)** — мозг системы, который проверяет безопасность, рассчитывает суммы и отдает данные.
3. **База данных (хранилище)** — место, где транзакции сохраняются надежно и не исчезают после перезагрузки страницы.

---

### 2. Выбор стека: почему именно так

Для старта не нужно усложнять проект сотнями библиотек:
- **Frontend**: React + Vite + TypeScript + Tailwind CSS. Быстрая сборка, строгая типизация, стили прямо в разметке.
- **Backend**: Node.js + Express + TypeScript. Легкий сервер, единый язык с фронтендом, минимум бойлерплейта.
- **База данных**: SQLite (через Prisma ORM) для локального старта за 0 секунд без поднятия сложных серверов, с легким переключением на PostgreSQL при деплое.
- **Структура репозитория**: Монорепозиторий (папка frontend/ и папка backend/ в одном проекте).

---

### 3. Архитектура: как разложить файлы по полочкам

#### Бэкенд (Backend) — Принцип "Ресторан"
Внутри папки backend/src/ код делится на 3 слоя:
1. **Controllers (Контроллеры / Официанты)**: принимают запрос от пользователя по HTTP (GET, POST), достают параметры и отдают ответ. Они НЕ считают баланс и НЕ лезут напрямую в базу.
2. **Services (Сервисы / Шеф-повара)**: здесь живет чистая бизнес-логика. Проверка, хватает ли денег, вычисление суммы расходов по категориям, валидация лимитов.
3. **Repositories / ORM (Хранилище / Кладовая)**: запросы к базе данных (найти транзакцию по id, сохранить новый расход, удалить запись).

#### Фронтенд (Frontend) — Модульная структура
Внутри папки frontend/src/ логика разбита по назначению:
- pages/ — экраны приложения (DashboardPage, AnalyticsPage, SettingsPage).
- widgets/ — готовые смысловые блоки (BalanceCard, TransactionList, ExpenseChart).
- features/ — интерактивные действия (форма добавления расхода AddTransactionForm, удаление).
- shared/ — переиспользуемые кнопки, инпуты и сетевой клиент для связи с бэкендом (api.ts).

### 5. Пошаговая инструкция запуска

После того как AI сгенерирует файлы:

1. **Терминал 1 (Бэкенд)**:
   ```bash
   cd backend
   npm install
   npx prisma db push
   npm run dev
   ```
   Сервер запустится на `http://localhost:5000`. В консоли должно появиться: `Server running on port 5000`.

2. **Терминал 2 (Фронтенд)**:
   ```bash
   cd frontend
   npm install
   npm run dev
   ```
   Открой браузер по адресу `http://localhost:5173`.

3. **Проверка**:
   - Добавь тестовый расход (например: "Кофе", 1500, категория "Развлечения").
   - Убедись, что баланс пересчитался автоматически.
   - Обнови страницу — данные должны сохраниться в SQLite и остаться на экране.
