# Выбор трекера задач: GitHub Projects

## Проблема
Необходим инструмент управления проектами для соло-разработки или небольшой команды (JF-1C, MeDev), который минимизирует переключение контекста (context switching), имеет удобные автоматизации и не требует лишних оплат или сложных настроек.

## Решение
Использовать **GitHub Projects** как основной трекер задач (слой планирования поверх Issues и Pull Requests).

### Основные возможности (2026)
- Доски (Board), таблицы (Table), таймлайн (Timeline).
- Кастомные поля (Status, Priority, Size, дата и т.д.).
- Автоматизации (когда Issue создаётся / закрывается / PR мержится — карточка двигается).
- Связь с репозиториями (один Project может собирать Issues из нескольких репо).
- Insights (базовые графики).
- Sub-issues и иерархия (эпик → задачи).
- Сохранённые виды (фильтры + группировки).

### Плюсы
- Полностью бесплатно.
- Живёт там же, где код — минимальный context switching.
- Issues и PR автоматически появляются в проекте.
- Идеально для соло и небольших команд.
- Автоматизации достаточно сильные для большинства задач разработчика.
- Не нужно ничего настраивать и платить.

### Минусы
- Слабая аналитика и отчётность (нет нормальных burndown, velocity, сложных дашбордов).
- Не очень удобен при обилии не-кодовых задач (маркетинг, поддержка, личные дела).
- Кросс-проектный обзор ограничен.
- Для больших команд с продактами/дизайнерами обычно не хватает.

### Важные нюансы (2026)
- **Sub-issues — киллер-фича:** Нативная поддержка (с 2024 г.) схемы "Эпик → задачи" (с прогрессом 3/8). Заменяет Linear для соло-разработчиков без лишнего оверхеда.
- **Единый дашборд:** Один Project может собирать Issues из JF-1C и будущих проектов (например, CareerHub), что решает проблему кросс-репозиторного трекинга.
- **Автоматизации:** Базовые вещи (PR opened -> In Progress, PR merged -> Done) работают из коробки. Всё, что сложнее (например, stale issues), требует настройки GitHub Actions через `gh` CLI.
- **Сохраненные виды (Saved Views):** Позволяют за пару минут создать дашборды: "только мои задачи", "только P0 этой недели", "timeline по всем проектам" — работают как мощные фильтры.

### Рекомендуемая структура проекта (прямо сейчас)
**Колонки (Статусы):**
- Backlog
- In Progress
- Review/Testing
- Done

**Custom fields:**
- **Priority:** P0 / P1 / P2
- **Area:** CRM / Auth / Learning / Infra / New Feature (Особенно полезно в монолитах типа JF-1C, чтобы фильтровать подсистемы без шума).
- **Sprint:** #1 / #2 / ...

### Вердикт
Zero friction: issues живут там же, где код, PR автоматически линкуются к задачам. Это оптимальный выбор для перехода на новые архитектуры (например, мультитенантность в JF-1C). Фича Milestones даёт честный roadmap без оверхеда Confluence. Если потом понадобится более мощная аналитика или работа с не-техническими людьми — можно добавить Linear или Plane, но начинать лучше с GitHub Projects.
