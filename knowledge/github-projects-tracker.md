# Выбор трекера задач: GitHub Projects

## Проблема
Необходим инструмент управления проектами для соло-разработки или небольшой команды (JF-1C, MeDev), который минимизирует переключение контекста (context switching), имеет удобные автоматизации и не требует лишних оплат или сложных настроек.

## Решение
Использовать **GitHub Projects** как основной трекер задач (слой планирования поверх Issues и Pull Requests).

### Основные возможности (2026)
- Доски (Board), таблицы (Table), таймлайн (Timeline).
- Кастомные поля (Status, Priority, Size, дата и т.д.).
- Автоматизации (когда Issue создаётся / закрывается / PR мержится — карточка двигается).
- Связь с репозиториями (один Project может собирать Issues из нескольких репо).
- Insights (базовые графики).
- Sub-issues и иерархия (эпик → задачи).
- Сохранённые виды (фильтры + группировки).

### Плюсы
- Полностью бесплатно.
- Живёт там же, где код — минимальный context switching.
- Issues и PR автоматически появляются в проекте.
- Идеально для соло и небольших команд.
- Автоматизации достаточно сильные для большинства задач разработчика.
- Не нужно ничего настраивать и платить.

### Минусы
- Слабая аналитика и отчётность (нет нормальных burndown, velocity, сложных дашбордов).
- Не очень удобен при обилии не-кодовых задач (маркетинг, поддержка, личные дела).
- Кросс-проектный обзор ограничен.
- Для больших команд с продактами/дизайнерами обычно не хватает.

### Вердикт
Очень хороший выбор как основной трекер задач для разработчика, чьи проекты уже лежат на GitHub. Для JF-1C и MeDev — более чем достаточно. Если потом понадобится более мощная аналитика или работа с не-техническими людьми — можно добавить Linear или Plane, но начинать лучше с GitHub Projects.
