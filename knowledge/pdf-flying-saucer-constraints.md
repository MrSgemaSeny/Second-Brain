# Flying Saucer (xhtml2pdf / iText): Строгие правила и ограничения

## 1. Подключение шрифтов (Кириллица)
Движок **игнорирует** теги `<link rel="stylesheet">` с внешними URL (например, Google Fonts) во время рендера PDF. Из-за этого текст откатывается на дефолтный шрифт (Helvetica), в котором **нет кириллицы** — русские символы просто исчезают (молча, без квадратиков).
**Решение:** 
Скачать `.ttf` файлы в `resources/fonts/` и строго регистрировать в коде через `ITextRenderer`:
```java
renderer.getFontResolver().addFont(fontPath, "Identity-H", true);
```
*(Параметр `true` включает subsetting — встраиваются только использованные глифы, PDF не раздувается).*

## 2. Ловушка Fat-Jar (Fly.io, Spring Boot)
При деплое `.ttf` файлы оказываются внутри архива (`jar:file:...`). Старый PDF-движок не умеет читать шрифты из архива через InputStream, ему нужен прямой путь к файлу в ОС (`/path/to/font.ttf`).
**Решение:** В `@PostConstruct` вытаскивать шрифты из `ClassPathResource` во временные файлы (`Files.createTempFile`) и использовать `tempFile.toAbsolutePath().toString()` для `addFont`.

## 3. Вёрстка (CSS)
Flying Saucer поддерживает только старый стандарт **CSS 2.1**.
- **Никаких `display: flex` или `display: grid`.** Используйте `float: left`, `display: inline-block` или `<table>`.
- **Никаких CSS-переменных** (`var(--color)`). Цвета нужно хардкодить (например, `#0d1117`).

## 4. Разрывы страниц (Page Breaks)
Блоки опыта, образования и проектов могут некорректно разрываться между страницами, оставляя заголовок на одной, а текст на другой.
**Решение:** Обязательно добавлять на карточки (классы `.item`, `.card`) правило:
```css
page-break-inside: avoid;
```

## 5. Цвет фона и поля страницы
По умолчанию Flying Saucer режет белые "печатные поля", даже если `body` залит цветом. 
**Решение:** Добавлять правило `@page`:
```css
@page {
    size: A4;
    margin: 0;
    background-color: #0d1117; /* Должен совпадать с фоном body */
}
```
