# Оптимизация памяти и контекста LLM: Архитектурные принципы и реализация

Настоящий документ фиксирует инженерную стратегию управления контекстным окном и долговременной памятью агента Antigravity в связке со Вторым Мозгом (Second Brain). Стратегия объединяет лучшие практики из ведущих Open-Source репозиториев:

1. **letta-ai/letta (MemGPT)** — Виртуальная иерархическая память агента.
2. **mit-han-lab/streaming-llm** — Attention Sinks и скользящее окно контекста.
3. **berkdurmus/adaptive-llm-memory-compressor** — Адаптивная компрессия и фильтрация токенов.
4. **NirDiamant/Agent_Memory_Techniques** — Паттерны разделения Episodic, Semantic и Procedural памяти.
5. **IAAR-Shanghai/Awesome-AI-Memory** — Таксономия и защита от отравления контекста.

---

## 1. Архитектура трёхуровневой памяти (Tiered Memory Model)

По аналогии с операционной системой, память агента разделена на 3 слоя:

```
+-------------------------------------------------------------+
| L1: Working Memory (ОЗУ / Активный промпт)                   |
| - Системные директивы (Attention Sink)                      |
| - .agents/CONTEXT.md (Текущее состояние проекта, <150 строк)|
| - Core Context (rules.md, me.md, projects.md)               |
+-------------------------------------------------------------+
                              ▲
                              │ (Чтение по необходимости через view_file)
                              ▼
+-------------------------------------------------------------+
| L2: Archival & Recall Memory (Диск / База знаний)           |
| - Second Brain context/ (стратегии, аудиты, гайды)          |
| - journal/YYYY-MM-DD/ (история завершённых задач)           |
| - decisions/ (ADR архитектурных решений)                    |
+-------------------------------------------------------------+
                              ▲
                              │ (Векторный поиск / grep_search)
                              ▼
+-------------------------------------------------------------+
| L3: Codebase & Telemetry (Исходный код и БД)                |
| - PostgreSQL schema, Flyway migrations, API DTOs            |
| - student_help_requests (Датасет реальных вопросов новичков)|
+-------------------------------------------------------------+
```

## 2. Реализация Attention Sinks (StreamingLLM)

### Проблема:
При длинных сессиях повторная отправка всей истории переполняет KV-кэш, увеличивает задержку (TTFT) и приводит к деградации логики ("Lost in the Middle").

### Решение:
1. **Первый запуск (invocationNum = 1)**:
   - Инжектится минимальный рабочий набор: `.agents/CONTEXT.md` + вайтлист Second Brain (`rules.md`, `me.md`, `projects.md`).
2. **Последующие шаги (invocationNum > 1)**:
   - Авто-инжекция отключается.
   - Передаётся только компактный однострочный анкор (Attention Sink):
     `[AI GUARD] Active Session. Directives: Zero emojis | Use native API tools | Strict Level-3 scope.`

## 3. Адаптивная фильтрация и компрессия (Adaptive Memory Compression)

### Правила фильтрации контекста:
1. **White-listing вместо Bulk-инъекции**:
   - Запрещено инжектировать все файлы `*.md` из `context/` скопом.
   - Инжектируются только общие правила и активные проекты. Специфичные документы других продуктов (`medev_resume_design.md`, `security_audit.md`) остаются в L2-памяти и читаются только по прямому запросу.
2. **Лимит строк (Hard Line Cap)**:
   - `.agents/CONTEXT.md` строго держится в пределах 150-200 строк.
   - Каждый инжектируемый файл из Second Brain обрезается до 120 строк.

---

## 4. Операционный регламент для разработчика

1. **Завершение задачи -> Новый чат**:
   - После прохождения тестов, записи в журнал и git push рекомендуется открывать новую сессию (`Ctrl+N` / `New Session`).
   - Агент мгновенно восстанавливает 100% рабочего контекста из `CONTEXT.md` за 1 шаг без сжигания токенов на старые логи.
2. **Точечные пути в промптах**:
   - Указывать целевые файлы прямо в запросе (например: `"измени LessonRow.tsx"`), что снижает количество промежуточных `grep_search` и экономит до 90% токенов за итерацию.
